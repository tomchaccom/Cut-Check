# KOMPAS

**의도를 코드로 옮긴다.** 목적지는 몰라도, 방향은 안다.

중학교 1~2학년이 모호한 요청을 받아 **성공을 정의하고 · 설계하고 · 코드로 옮기고 · 스스로 판정하는** 파이썬 수업 도구입니다.
화면은 시작을 도와줄 뿐, 판단은 하나도 대신하지 않습니다. (예전 이름: Cut & Check)

---

## 핵심 흐름

### 강사

```
가입 ─▶ 교실 만들기 ─▶ 학생 계정 만들기 ─▶ 미션 만들기 ─▶ 수업 중: 알림 보기 ─▶ 학생 상세에서 한마디
```

1. **교실 만들기** — 가입은 강사만 합니다. 왼쪽 사이드바에 교실이 쌓입니다.
2. **학생 계정 만들기** — 이름·아이디를 적으면 비밀번호와 함께 한 번 보여 줍니다. 필요하면 **레벨 테스트를 지정**합니다 — 문제지 하·중·상 중 하나를 고르고, 기록(날짜·맞힌 수·문항별)과 레벨은 강사에게만. 두 달이 지나면 다시 지정하라는 알림.
3. **미션 만들기** — 두 가지 방식.
   - **단계별로**: 수업 내용 → 개념 확인 → 이야기 고르기 → 문제 확인. AI 가 모범 답안을 쓰고 강사 브라우저에서 돌려 자료별 정답을 붙입니다. 강사가 고쳐서 확정해야 학생에게 보입니다.
   - **한 번에**: 수업 내용만 넣고 바로 초안.
   - 강사마다 생성 횟수가 정해져 있습니다(관리자가 늘려 줌).
4. **수업 중 — 오른쪽 알림** — 점수가 아니라 타이밍만.
   - **칭찬 타이밍**: 미션을 마쳤어요 · 성공 조건을 스스로 바꿨어요 · 에러 뒤 스스로 고쳐 다시 돌렸어요 · 나침반 방향이 겹쳐요(골라 주세요)
   - **살펴볼 것**: 하드코딩일 수 있어요 · 튜터에게 5번 물었어요
   - **레벨 테스트**: 테스트를 마쳤어요 · 두 달 지났어요
5. **학생 상세** — 그 학생이 한 일을 시간순으로, 설계도와 코드를 나란히, 튜터 대화와 수업에서 짚을 거리. **나침반**은 이해·설계·구현·검증 방향마다 예/아니오 3항목을 보고, 최근 5개 미션을 모아 바늘 하나로 보여 줍니다. 방향이 서로 지워지면 강사가 고릅니다. 강사는 **한마디**를 써서 보냅니다. 칭찬의 말은 기계가 아니라 강사가 씁니다.

### 학생

```
로그인 ─▶ (레벨 테스트) ─▶ 미션 고르기 ─▶ 01 문제 ─▶ 02 성공 ─▶ 03 설계 ─▶ 04 코딩 ─▶ 05 정리
```

1. **로그인** — 강사가 만들어 준 아이디로. 지정된 학생은 레벨 테스트부터(맞았는지·난이도는 보이지 않습니다).
2. **01 문제** — 요청은 일부러 모호합니다. 방법은 어디에도 없습니다.
   > 창고에 주문서가 들어왔어요. 상품이 몇 개인지 알려주세요.
3. **02 성공** — 무엇이 성공인지 스스로 고릅니다. 보기에는 함정("이번 결과가 나오면 성공")이 섞여 있고, 어느 게 맞는지 알려 주지 않습니다.
4. **03 설계** — 할 일 카드를 담고 순서를 맞춥니다(필요 없는 카드도 섞여 있습니다).
5. **04 코딩** — 설계도 옆에서 코드를 쓰고 자료 3개로 실행합니다. 마지막 자료는 늘 **반례**입니다. 막히면 오른쪽 **튜터**에게 묻습니다 — 문법은 알려 주고, 풀이는 되묻습니다.
6. **05 정리** — "내 성공 조건을 지켰나"를 학생이 판정하고, 처음과 달라진 점을 한두 문장으로 남깁니다.
7. 강사가 한마디를 보내면 **내 기록**에 내 나침반(최근 미션들의 방향)이, 미션을 다시 열면 선생님 말이 보입니다.

### 관리자

강사별 생성 횟수 보기 · 늘리기 · 끄기, 최근 생성 기록, 신규 가입 기본 횟수.

자세한 화면별 안내는 [docs/수업-흐름.md](docs/수업-흐름.md).

## 이 도구가 하지 않는 것

> **시작은 대신해주고, 판단은 하나도 대신하지 않는다.**

| 하지 않는 것 | 왜 |
|---|---|
| 정답과 대조하는 채점 · "틀렸어요" | 채점하는 순간 학생은 우리 답을 추측하러 간다. 판정은 학생이 한다 |
| 점수 · 순위 · 정답률 · 연속 출석 | 숫자를 띄우면 강사는 줄을 세우고 학생은 결과를 맞히러 간다 |
| 기계가 쓰는 칭찬 | 타이밍만 알려 주고 말은 강사가 한다 |
| 다음에 할 일 추천 · 실행 전 힌트 | 판단 대행의 가장 흔한 형태 |
| 학생 화면에 반 전체 현황 | 수업이 속도 경쟁이 된다 |

예외 둘(강사 화면에만): 레벨(상·중·하)과 나침반의 체크 항목·점수. 학생에게는 가지 않습니다.
약속은 코드가 지킵니다 — 이벤트에 점수류 필드를 넣으면 저장 함수가 거절하고(`js/core/events.js`), 화면에 금지 단어가 뜨면 테스트가 깨집니다(`test/smoke.js`).

## 해보기

```bash
git clone https://github.com/tomchaccom/Cut-Check.git
cd Cut-Check
python3 -m http.server 8123
```

`localhost:8123` 을 열면 소개 페이지입니다. 서버 없이 열면 이 브라우저 안에서만 도는 **로컬 모드**(학생·강사 화면을 혼자 돌려 볼 수 있음),
로그인·교실·학생 계정·AI(미션 생성·튜터·나침반)는 Vercel 함수 + Supabase 를 붙였을 때 동작합니다 — [docs/server.md](docs/server.md).
서버는 기록의 조건이 아니라 사본입니다. 와이파이가 끊겨도 학생이 누른 것은 사라지지 않습니다.

| 주소 | 화면 |
|---|---|
| `/auth.html` | 로그인 · 강사 가입 |
| `/sentence.html` | 학생 화면 |
| `/teacher.html` | 강사 화면 |
| `/admin.html` | 관리자 화면 |
| `/philosophy.html` | 설계 철학 한 장 |
| `/print.html` | 수업 준비물(인쇄용) |

## 구조

```
화면     landing · auth · sentence(학생) · teacher(강사) · admin · philosophy · print
js/core  판단의 규칙 — 이벤트 계약, 접기(fold), 실행 엔진, 알림 · 나침반 그림, 조사 계산, AI 출력 검사
js/data  바깥 세계 — localStorage · Supabase · 오프라인 발신함
js/ui    화면 — DOM 만 만진다
api/     Vercel Python 함수 — 미션 생성, 튜터와 가드레일, 수업에서 짚을 거리, 나침반, 학생 계정, 생성 한도, 관리자
```

번들러·ES 모듈 없이 정적 파일만 씁니다 — 강사가 파일을 열어 고칠 수 있어야 합니다.
층의 경계(core 는 저장소·화면을 모른다)는 `test/layer.test.js` 가 지킵니다.
테스트 목록과 작업 규칙은 [CLAUDE.md](CLAUDE.md).
