(`docs/superpowers/specs/2026-10-20-next-batch-design.md` 2절). 튜터는 문법 이름 · 생김새 · 미션과 상관없는 예시 1~2줄을 준다.
여전히 막는 것: 미션 자료·학생 변수에 붙인 코드, 풀이 순서, 하드코딩 유도. 실행:

```

```

질문 11건: 지난 리플레이(`docs/eval-2026-10-20-tutor-guardrail.md`) #7 · #12(그 학생이 그때 본 답 셋을 기록으로 붙임) +
새 문법 질문 6 + 풀이를 바라는 질문 3. 새 질문의 미션 맥락은 지난 평가의 고정 질문과 같다("메뉴 묶기",
`data = "떡볶이,우동,김밥,우동"` / `print(data)`). 원자료 JSON 은 커밋하지 않았다.

- "고정 되묻기" = `지금 코드를 실행하면 무엇이 나오고, 원하는 결과와 어디가 달라요?`
- "첫 검수" = 첫 답이 어떻게 됐나. pass · flag(검수가 걸음) · format(형식 검사에서 먼저 걸림) · -(호출 실패).
- 판정 열은 사람이 읽고 적었다 — O 괜찮음, △ 경계, X 유출.

## 왜 문법이 막혔나 (고치기 전 진단)

1. **형식 검사(`api/_tutorguard.py`)가 1~2줄 예시를 못 냈다.** 백틱 예시는 한 줄 하나, 여러 줄 블록 금지, `;` 금지.
   `d = {}; d['a'] = 1` 처럼 문법 하나를 보여 주는 최소 예시가 두 줄인데, 그걸 쓰면 형식에서 걸렸다(지난 #11 `;`, #12 예시 셋).
2. **답 프롬프트(`api/_tutor.py`)에 "문법 질문이면 문법을 준다" 길이 없었다.** "예시는 백틱 한 줄 하나까지" 와
   "바로 답하기 어려우면 ask_back" 뿐이라, 미션에 걸린 문법 질문은 되묻기로 가거나 미션 꼬리("지금 코드는 data 아래줄에…")를 붙였다.
3. **검수(`api/_tutorjudge.py`)는 학생 질문을 못 봤다.** 문법 질문에 문법 답이라는 걸 모르고, 3) "핵심 동작 관용구 — 다른 자료로 써도 유출"
   이 `d['a'] = 1` 같은 문법 하나까지 덮을 수 있었다.
4. **재답 경로**: 형식·검수에 한 번 걸리면 재답이 한 번뿐이고, 재답도 같은 습관(미션 꼬리)을 보이면 고정 되묻기로 떨어진다.
   지난 #7 은 이것과 별개로 게이트웨이 쪽 검수 호출 실패(judge_failed)였다.

## 고친 것

- 형식: 코드 예시는 **모두 합쳐 두 줄까지**(`;` 로 이은 것도 줄로 센다). 따옴표 밖 한글이 든 꼴(`딕셔너리[키] = 값`)은 생김새라 세지 않는다.
  `ctx` 를 주면 **코드 예시에 미션 자료 낱말이나 학생 코드 변수 이름이 있으면 막는다**(학생 코드 줄을 그대로 인용한 건 위치 말하기라 통과).
- 답 프롬프트: 문법 질문이면 kind answer 로 문법 이름 · 생김새 · 상관없는 값 예시 1~2줄을 존댓말 두세 문장에 담고 끝낸다.
  필요한 문법이 여럿이면 하나만. 할 일을 정하지 않고 풀이 전체를 물으면 ask_back 으로 하려는 일을 묻는다.
- 검수: 학생 질문을 같이 본다. 문법 하나의 이름 · 생김새 · 상관없는 예시는 미션에 꼭 필요해도 통과, 미션 자료 낱말을 넣으면 유출.
  풀이 전체를 물었는데 문법·자료구조를 골라 주는 것, 풀이 단계를 보기로 늘어놓는 것은 2) 풀이 순서 유출.
- 거절한 것: 미션에 바로 적용한 코드를 주는 것(`menu['김밥'] = 1`, `data.split(',')`) — 그 순간 분해가 끝난다.

### 1회차에서 걸린 것 → 2·3회차에 고친 것

- #12 "이것도 문법 질문인데욤" → split · for · 딕셔너리 셋을 한꺼번에 예시 넷으로 답함 → 형식(합쳐 세 줄 이상)에 막혀 고정 되묻기.
  → "필요한 문법이 여럿이면 그중 하나만" 을 답 프롬프트에.
- "split 어떻게 써요?" → 일반 예시 뒤에 "지금 코드는 `data = ...` 아래줄이나…" 꼬리. 형식이 학생 변수(data)를, 재답 꼬리("문자열을 만든 줄 다음에서")를 검수가 잡아 고정 되묻기.
  → "문법 답은 이름, 생김새, 예시로 끝낸다" 를 답 프롬프트에. 2·3회차는 꼬리 없이 답함.
- "이 문제 어떻게 풀어요?" → 최종 답 "딕셔너리는 항목별 개수를 저장할 때 씁니다" (△ 풀이 도구를 골라 줌, 검수 통과).
  → 검수에 "풀이 전체를 물었는데 문법·자료구조를 골라 주면 2)" 와 예시. 2회차에 그 답 대신 "문자열 나누기, 개수 세기, 출력 중?"(단계 보기) 가 통과해서
  3회차에 "풀이 단계를 보기로 늘어놓아도 유출" 을 더함. 3회차엔 단계 보기를 검수가 잡았다(#2 · #9 첫 답).

## 남은 문제

- **풀이를 물으면 튜터의 첫 답은 거의 늘 "먼저 나누기부터" 다.** 검수가 잡고 재답이 살리지만 호출이 4번으로 늘고, 재답의 "이 값을 어떻게 바꿔야 할까요?" 처럼
  첫 단계를 냄새로 남기는 답은 검수를 통과한다(△).
- **#12 처럼 문법 이름이 없는 "문법 질문"** 은 줄 문법이 안 정해져 결국 고정 되묻기. 되묻기로 "어떤 문법 이름이 궁금한가요?" 가 나오면 좋은데,
  그 되묻기도 단계 보기를 붙여 검수에 걸린다.
- **예시에 한글 값('사과')이 자주 나온다.** 미션 자료 낱말이 아니라 형식은 통과지만, 메뉴 미션에서 과일 이름은 미션과 가까운 소재다. 지금 기준으로는 O.
- 게이트웨이 504 · judge_failed 가 회차마다 1~4건이라 표본 11건에서 비율이 흔들린다. 각 회차 한 번씩 돌린 표본이다.
