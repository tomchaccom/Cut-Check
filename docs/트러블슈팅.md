# 트러블슈팅

문제가 생기면 **고치기 전에 여기부터 찾는다.** 같은 문제가 있으면 적힌 대로 해결한다.
없으면 직접 해결하고, **실제로 해결을 확인한 뒤에만** 아래 형식으로 추가한다.
추측이나 해결 못 한 문제는 적지 않는다 — 여기 적힌 건 전부 검증된 해결법이어야 한다.

## 형식

```markdown
### 한 줄 증상 (검색되는 말로: 에러 문구, 화면 이름, 명령어)

- 날짜 · 커밋: 2026-10-17 · abc1234
- 증상: 무엇을 했을 때 무엇이 보였나. 에러 문구는 그대로
- 원인: 왜 그랬나
- 해결: 무엇을 바꿨나 (파일:줄)
- 확인: 해결됐다는 걸 무엇으로 확인했나 (명령어, 테스트)
```

---

### 새 워크트리에서 띄운 Claude 세션이 "Accessing workspace … trust" 화면에서 멈춤

- 날짜 · 커밋: 2026-10-16 · (설정 변경, 코드 커밋 없음)
- 증상: `orca terminal create --command "teamclaude run …"` 으로 띄운 세션이 신뢰 확인에서 멈춘다.
  `orca terminal wait` 가 `blockedReason: agent-trust-workspace`. `orca terminal send` 로 `1` 은 무시되고,
  Enter 는 커서가 있던 **"No, exit"** 를 골라 세션이 종료됐다.
- 원인: 처음 여는 폴더는 `~/.claude.json` 의 `projects[<경로>].hasTrustDialogAccepted` 가 없다.
- 해결: `~/.claude.json` 을 백업하고 그 경로의 `hasTrustDialogAccepted` 를 `true` 로 넣은 뒤 세션을 다시 띄운다.
  키 입력으로 넘기려 하지 않는다.
- 확인: 재실행 후 `orca terminal wait --for tui-idle` 가 `satisfied: true`, 입력창이 뜸.

### macOS 에서 `find -newermt "-10 minutes"` 가 최근 수정 파일을 못 찾음

- 날짜 · 커밋: 2026-10-16 · (셸 스크립트, 코드 커밋 없음)
- 증상: "10분간 수정 없음" 감시가 8분 전에 수정된 파일이 있는데도 조용하다고 판정했다.
- 원인: BSD `find` 는 `-newermt` 의 상대 시간 표현을 의도대로 해석하지 않는다.
- 해결: 수정 시각을 초로 받아 직접 비교한다.
  `find … -exec stat -f '%m' {} + | sort -rn | head -1` 과 `date +%s` 의 차이.
  시각 문자열(`%H:%M`)로 정렬하지 않는다 — 어제 19시가 오늘 02시보다 뒤로 정렬된다.
- 확인: 같은 디렉터리에서 마지막 수정 02:57:31 을 잡고, 10분 뒤 03:08 에 정확히 "조용함" 으로 판정.

### 미션 초안 요청이 `json_schema` 로 매번 400 `upstream_rejected` ("Provider returned error")

- 날짜 · 커밋: 2026-10-16 · 5da730e
- 증상: `openai/gpt-5.4-mini` 로 바꾼 뒤 eval 에서 `초안 · json_schema → 400` 23/23. 매번 `json_object` 로 내려가 형식 보장이 사라졌다. 유형 고르기(작은 스키마)는 통과.
- 원인: 게이트웨이 뒤 OpenAI 는 스키마에 `$defs`·`$ref` 가 있거나, `additionalProperties: false` 가 없는 객체가 있으면 거절한다. pydantic `model_json_schema()` 는 둘 다 해당.
  둘 중 하나만 고치면 여전히 400 이다 — 작은 스키마로 하나씩 보내서 확인했다.
- 해결: `api/_generate.py` 의 `_flat()` 이 `$ref` 를 펼치고 모든 객체를 닫은 뒤 보낸다.
- 확인: 14개 유형 스키마 직접 호출 14/14 OK, 다음 eval 에서 `초안 · json_schema → ok` 23회·400 0회. `test/test_generate.py` 가 펼친 스키마를 검사한다.

### `pickle-general` 이 첫 토큰 없이 정확히 30초에 끊김 (`RemoteDisconnected`, `client_disconnected`)

- 날짜 · 커밋: 2026-10-16 · 5da730e
- 증상: 짧은 요청도 30.1초에 끊김. 스트리밍은 200 헤더만 오고 본문 0바이트. `/v1/models` 는 0.1초에 응답. 대시보드에는 `client_disconnected`.
- 원인: 자체 서빙 모델이 응답을 시작하지 못하고, 앞단 nginx 가 30초에 연결을 닫는다 (운영자 쪽 문제, 우리 요청·키 문제 아님).
- 해결: 같은 키의 유료 모델로 우회. 기본 `openai/gpt-5.4-mini`, 바꾸려면 Vercel 환경변수 `LLM_MODEL`.
- 확인: 같은 시각 `openai/gpt-5.4-mini` 1.1초 응답, eval 10/10 생성.

### `/api/create-student` 가 502 "계정을 만들지 못했어요" — admin 생성이 500 `P0001` "students.invalid 주소는 선생님 화면에서만 만들 수 있어요."

- 날짜 · 커밋: 2026-10-18 · 5da730e
- 증상: 선생님 화면 `학생 추가` 가 항상 502. `POST /auth/v1/admin/users` 를 `app_metadata: {role: 'student'}` 로 직접 불러도 HTTP 500 `{"code":"P0001", ...}`.
- 원인: GoTrue 의 admin 계정 만들기는 `auth.users` 에 provider 정보만 담아 INSERT 하고, 요청한 `app_metadata` 는 같은 트랜잭션의 다음 UPDATE 에서 넣는다. AFTER INSERT 트리거 `handle_new_user`(20261018000000)는 role 을 못 보고 학생 도메인을 거절했다.
- 해결: `supabase/migrations/20261018000001_student_role_on_update.sql` — INSERT 트리거는 거절하지 않고(학생 표시 없으면 강사 행), `AFTER UPDATE OF raw_app_meta_data` 트리거가 role 이 `student` 로 바뀔 때 프로필을 학생 + `login_id` 로 바꾼다. 공개 가입으로 학생 이메일을 먼저 차지한 계정은 `api/_accounts.py` 가 생성 409 때 `GET /auth/v1/admin/users?filter=<이메일>` 로 찾아(이메일 정확히 일치만) 학생 표시가 없으면 지우고 한 번만 다시 만든다. 호출이 최대 9번이 돼 `TIMEOUT` 4→3초(9×3=27 < 30).
- 확인: 로컬 `supabase start`(Docker) 에서 옛 함수만 둔 상태로 admin 생성 → 500 `P0001` 재현, 새 마이그레이션 적용 뒤 같은 호출 200 + `profiles` role `student`·`login_id` 채워짐. 같은 로컬 스택에서 `handle()` 로 공개 가입한 `kim-2@students.invalid`(강사 행) → 만들기 200(학생 행·수강 1줄), 다시 만들기 409, reset 200. `python3 test/test_accounts.py` 통과. 운영(2026-10-18): 마이그레이션 적용·배포 뒤 headless 브라우저로 강사 로그인 → 학생 계정 만들기 200 → 비밀번호 다시 만들기 → 그 아이디로 학생 로그인 → 교실 보임. 확인용 계정은 지웠다.

### 비밀번호 다시 만들기를 눌렀는데 새 비밀번호가 안 보이고, 학생은 예전 비밀번호로 못 들어옴

- 날짜 · 커밋: 2026-10-18 · e839e93
- 증상: 운영에서 "비밀번호 다시 만들기" 요청은 200 인데 화면에 새 비밀번호 상자가 없다. 같은 때 직접 쓴 아이디가 `<교실코드>-1` 제안으로 바뀌어 그 아이디로 계정이 만들어졌다.
- 원인: 결과 상자를 명단 행에 붙였는데 `loadStudents()` 가 명단을 다시 그리면서 행째 사라졌다. 교실이 하나면 자동으로 열리는데 같은 교실을 또 누르면 명단 불러오기가 두 번 겹친다. `suggestLogin()` 은 그때마다 아이디 칸을 덮어썼다.
- 해결: 결과(만들기·다시 만들기)는 명단 밖 `#ns-result` 에 학생 이름과 함께 보인다. 아이디 칸은 비었거나 직전 제안 그대로일 때만 채운다.
- 확인: E2E 에 "직접 쓴 아이디·새 비밀번호가 명단을 다시 그려도 남는다" 추가. 운영 headless 로 직접 쓴 아이디 `m9676u-qa…` 가 그대로 만들어지고, 다시 만든 비밀번호로 학생 로그인 성공.

### E2E 가 갑자기 여럿 실패하는데 코드는 멀쩡함 — 다른 워크트리의 서버가 같은 포트에 떠 있음

- 날짜 · 커밋: 2026-10-20 · 환경 문제 — 코드 수정 없음
- 증상: 새 워크트리에서 `CC_BASE=http://localhost:8131 npx playwright test` 가 12개 실패(코드 문제 없이 거짓 실패).
- 원인: 8131 에 이전 작업의 `python3 -m http.server` 가 남아 있었고 그 서버는 **다른 워크트리**를 서빙하고 있었다. 포트가 열려 있으니 테스트는 에러 없이 엉뚱한 파일에 붙는다.
- 해결: 남은 서버를 끄고 이 워크트리를 `--directory` 로 지정해 다른 포트(8133)에 띄운다. `python3 -m http.server 8133 --directory <워크트리 경로>` 후 `CC_BASE=http://localhost:8133`.
- 확인: 같은 E2E 를 8133 에서 다시 돌려 통과(playwright 43 passed). 포트를 쓸 때는 `lsof -i :<포트>` 로 누가 열었는지 먼저 본다.

### 정답 보기 문구가 "7가" 로 나옴 — `hangul.hasBatchim` 이 숫자 7 을 받침 없음으로 계산

- 날짜 · 커밋: 2026-10-20 · a34d5c8 (수정) · 5da730e (기록)
- 증상: 함정 보기(이번 결과를 성공으로 삼는 문장)에 `hardcodeOption('주문서 1', '7')` 이 "7가" 로 시작하는 문장을 만들었다("7이" 여야 한다).
- 원인: 숫자는 읽는 소리의 끝 받침으로 정한다. 받침이 있는 숫자(1 일, 3 삼, 6 육, 7 칠, 8 팔, 10 십…) 표에서 `7`(칠)이 빠져 있었다.
- 해결: `js/core/hangul.js` 의 받침 있는 숫자 목록에 `'7'` 을 더하고 `test/hangul.test.js` 에 7 을 추가했다.
- 확인: `node test/hangul.test.js` 통과. 같은 값으로 만든 함정 보기가 "7이" 로 나온다.

### 단계별 생성의 "따로 푼 답"이 거의 늘 에러 — 모델이 `data` 에 자료 세 개가 다 들어 있다고 읽음

- 날짜 · 커밋: 2026-10-20 · 완성 확인 커밋 (`api/_steps.py` `solve`)
- 증상: 완성 확인 1회차에서 따로 풀기 16개 중 13개가 `IndexError`·`TypeError`(`'int' object is not subscriptable`) 로 끝났다. 따로 푼 코드는 `for s in data: print(s.split(',')[2])` 꼴.
- 원인: 프롬프트가 자료 세 개를 나열하고 "학생 코드가 data = <값> 으로 받는다"고만 해서, 모델이 `data` 를 자료 목록 전체로 읽었다.
- 해결: "data 에는 아래 자료 가운데 하나의 값만 들어 있다. 같은 코드를 자료마다 따로 돌린다" + `data = <자료 1 값>` 예를 프롬프트에 넣었다.
- 확인: `test/test_steps.py` 에 문장 검사 추가. 같은 16개를 다시 돌려 에러 0, 따로 푼 답과 같음 3 → 13 (`docs/eval-2026-10-20-stepwise-gen.md`).

### 강사 화면 초안의 상황이 "곤란해요.누가" 처럼 붙어서 저장됨

- 날짜 · 커밋: 2026-10-20 · 완성 확인 커밋 (`api/_steps.py` `_assemble`)
- 증상: 4단계 초안의 상황 칸에서 두 문장 사이 띄어쓰기가 없다. 확정하면 붙은 문장이 그대로 학생에게 간다.
- 원인: 모델이 상황 두 문장을 줄바꿈으로 나눠 보냈고, 강사 화면의 한 줄 `<input>` 은 값의 줄바꿈을 지운다(공백으로 바꾸지 않는다).
- 해결: 서버가 초안을 조립할 때 제목·상황·요청의 공백(줄바꿈 포함)을 한 칸으로 줄인다.
- 확인: `test_steps.py` "상황의 줄바꿈은 공백 하나로" 추가. headless 스크린샷(`docs/수업-흐름/t5-stepwise-4-draft.png`)에서 띄어쓰기가 보인다.
