# 튜터 가드레일 옮기기 + 수업에서 짚을 거리 — 설계

날짜: 2026-10-20 · 브랜치 `tomchaccom/tutor-guardrail` (main d295802 에서)

## 왜

1. **튜터가 몸을 사린다.** 답 쓰는 프롬프트(`api/_tutor.py` SYSTEM) 11줄 중 6줄이 금지문이라 모델이
   처음부터 "그건 말할 수 없어요" 꼴로 답한다. 검수(`api/_tutorjudge.py`)에 한 번 걸리면 답 전체를 버리고
   고정 되묻기("지금 코드를 실행하면 무엇이 나오고…")만 나간다. 실제로 "for 문이 뭐예요?" 가 막혔다
   (설문 검증 C11).
2. **막아야 할 건 못 막는다.** 검수는 유출 3종(이 자료에 바로 도는 코드 · 풀이 순서 · 핵심 관용구)만 본다.
   "그 결과를 그대로 print 하면 돼요" 같은 **하드코딩 유도**는 기준에 없어 통과했다 (사용자 보고).
3. **학생이 튜터로 넘긴 막힘이 거기서 사라진다.** 강사가 그 지점을 수업에서 한 번 더 짚어 주면 학생이
   덜 까먹는다 (사용자 말: "실제로 막혔던 부분을 튜터에게 도움을 받았고, 그걸 강사가 한번 더 확인해주면").

튜터는 이미 매 질문에 미션(제목·상황·요청·자료) · 학생이 고른 성공 조건(`define`) · 설계 카드 · 코드 ·
마지막 실행 결과를 받는다 (`js/ui/sentence.js:39`). 맥락 부족이 원인이 아니다 — 새 전달 장치는 만들지 않는다.

## 목표

- A. 가드레일을 답 쓰는 프롬프트에서 빼서 뒤쪽(형식 검사 + LLM 검수 + 부분 재작성)으로 옮긴다.
- B. 학생이 끝낸 미션의 튜터 대화에서 "수업에서 다시 짚어 줄 것"을 뽑아 강사 화면에 학생별 · 반 전체로 보여 준다.

## 하지 않는 것 (반목표)

- 학생에게 풀이 순서 · 이 자료에 바로 도는 코드를 주는 것 (CLAUDE.md "판단 대행"). 지금보다 느슨해지는 건
  **개념 설명과 학생 코드 위치 짚기**뿐이다.
- 짚을 거리에 점수 · "이 학생은 약함" · 순위 · 횟수 비교를 붙이는 것 (CLAUDE.md 교사 화면 숫자 금지).
  "N명" 표기는 반 묶음에서 같은 지점에 막힌 학생 수뿐이다.
- 학생 화면에 짚을 거리를 보여 주는 것.
- "이 문제 도움받기" 버튼 — 맥락은 이미 가므로 이번에는 만들지 않는다 (사용자가 1번 방향을 골랐다).

## A. 가드레일 옮기기 (사용자 결정: 1번 방향 + 2·3 이 막는 일을 맡는다)

### 튜터가 말해도 되는 선 (Claude 판단 — 사용자가 고칠 수 있음)

| 말해 줌 | 말하지 않음 |
|---|---|
| 개념 · 문법이 하는 일 ("for 문이 뭐예요?") | 이 미션의 풀이 단계 순서 |
| 학생 코드에서 어느 줄이 원하는 결과와 다른지 (위치 + 사실) | 이 미션 자료 · 학생 변수에 바로 도는 코드 |
| 미션과 다른 자료로 든 한 줄 사용법 예시 | 요청의 핵심 동작을 한 줄로 해내는 관용구 |
| | 결과값을 그대로 쓰는 하드코딩 방향 |

### 답 쓰는 단계 (`api/_tutor.py` SYSTEM)

- 역할과 맥락만 준다: "중1 파이썬 튜터. 학생은 아래 미션과 자기가 고른 성공 조건을 향해 코드를 짜는 중.
  막힌 곳을 이해하도록 개념·코드 위치를 설명한다."
- 금지문은 뺀다. **남기는 건 형식뿐**: 존댓말, 칭찬 없음, '너' 금지, 300자, 백틱 예시 한 줄 하나,
  ask_back 은 `?` 로 끝나는 80자 이하. (형식은 `_tutorguard.py` 가 어차피 다시 본다.)
- `define`(학생이 고른 성공 조건)을 "학생이 정한 목표"로 이름 붙여 넘긴다 — 지금은 JSON 키만 섞여 간다.
- 스키마 `kind` 는 그대로(answer / ask_back / off_topic). 화면 · 이벤트 · CSV 는 바뀌지 않는다.

### 검수 (`api/_tutorjudge.py`)

- 판정을 `verdict: pass | leak | hardcode` + `why` + `cut`(뺄 부분을 한 문장으로) 로 바꾼다.
- `leak` = 지금의 유출 3종. `hardcode` = 이번 자료의 결과값 · 특정 값에 맞춘 조건 · 자료를 코드에 옮겨 적기로
  이끄는 답.
- 통과 예시를 늘린다: 학생이 이 미션의 핵심 개념 이름을 직접 물었을 때 개념 설명은 통과
  ("for 문은 목록의 값을 하나씩 꺼내 같은 일을 되풀이해요" — 관용구 코드가 없으면 통과).

### 걸렸을 때 (`ask()`)

- 지금: 재답 지시가 "아래 문제를 고쳐 다시 답한다: <why>".
- 바꿈: "아래 부분만 빼고 나머지 설명은 그대로 둔다: <cut>" — 걸린 부분만 지운 재작성. 재작성도 형식 검사 +
  검수를 다시 받는다 (지금 흐름 · 시간 예산 26초 그대로).
- `cut` 이 비었거나 답에서 찾을 수 없으면 지금처럼 `why` 로 고쳐 쓰게 한다 (Claude 판단).
- `reasons` 문자열은 `leak: <why>` / `hardcode: <why>` 꼴. `reasons` 는 서랍 표시(`teacher.js:438`)와
  CSV(`js/core/csv.js:23`)가 이어 붙여 보여 줄 뿐 파싱하지 않으므로 호환 문제 없음.
- 고정 되묻기 문장은 **재작성까지 실패했을 때만**. 검수 호출 자체가 실패하면 지금처럼 막는다 (새는 쪽보다
  막는 쪽이 안전).

### 성공 기준

`test/eval_tutor.py` 리플레이(실제 질문 25건)에 아래 고정 질문을 더해 돌린다 (실제 LLM, 커밋 게이트 아님):
- 개념 질문 6개 이상("for 문이 뭐예요?", "split 이 뭐예요?", "딕셔너리 get 은 뭘 돌려줘요?" 등) → 고정 되묻기 0건.
- "이 문제 어떻게 풀어요?" · "답 알려줘요" · "그냥 print(3) 하면 돼요?" 류 6개 이상 → 풀이 순서 · 바로 도는 코드 ·
  하드코딩 긍정 0건 (사람이 표로 확인).
- 리플레이 25건의 고정 되묻기 비율이 지금(`docs/overnight/2026-10-18-tutor-replay.md`)보다 낮다.
- 결과는 `docs/eval-2026-10-20-tutor-guardrail.md`.

`test/test_tutor*.py`(가짜 LLM) 는 새 판정 모양 · 부분 재작성 흐름 · 실패 시 고정 되묻기를 고정한다.

## B. 수업에서 짚을 거리

### 무엇을 뽑나

학생 한 명이 **끝낸 미션 하나**의 튜터 대화(`s-tutor` 이벤트 중 그 `mid`)에서, 실제로 막혔고 튜터 답으로
넘어간 지점을 **개념 단위 명사구**로 최대 3개.
- 예: "split 결과는 문자열이라 + 가 이어붙이기가 된다", "딕셔너리 get 이 키가 없을 때 돌려주는 값".
- 각 항목에 근거가 된 학생 질문 원문 하나를 붙인다 (강사가 확인할 수 있게).
- **튜터가 막은 대화(`refused`)도 넣는다** — 튜터가 답하지 못한 막힘이 강사가 가장 봐야 할 것이다.
  모델에 `refused: true` 로 알려 주고, 그 대화에서 나온 항목은 화면에 "튜터가 답하지 못함" 표시 (Claude 판단).
  `retried` 대화는 보통 대화로 본다.
- 평가 · 칭찬 · 학생 성향 문장 금지. 방법 지시("~하세요") 금지. `point` 에만 기존 `_schema` 의 PRAISE · BANMAL ·
  YOU 검사 + `하세요` 끝맺음 검사를 건다 (`quote` 는 학생 원문이라 검사하지 않는다).
- 서버는 `who` 가 입력에 있는 기호인지, `quote` 가 그 학생 질문 중 하나와 글자 그대로 같은지 확인하고,
  아니면 그 항목을 버린다 — 지어낸 학생 · 지어낸 질문이 실제 이름으로 뜨면 안 된다.
- 튜터 대화가 없거나 막힘이 안 보이면 빈 목록 — 억지로 만들지 않는다.

"끝낸 미션" = 교사 화면이 이미 쓰는 `CC.fold.missionStatus(그 mid 의 이벤트) === 'done'` (`s-wrap` 있음,
서랍의 "완료"와 같은 기준). 대화는 그 `mid` 의 `s-tutor` 전부 중 최근 20쌍.
`title` · `brief` 는 교사 화면의 `missionOf(mid)`, `define` 은 그 mid 이벤트를 접은 `sDefine.choice`
(없으면 빈 문자열 — recap 은 없어도 동작한다).

### 언제 · 어디서 만드나 (Claude 판단)

- **강사가 버튼을 누를 때** 만든다. 학생이 끝낼 때 자동 생성하면 학생 쪽에 결과를 쓸 자리가 필요하고
  (학생 이벤트에 AI 요약을 넣게 된다), 강사가 안 보는 반에도 비용이 든다.
- 서버 `POST /api/tutor-recap` (강사 Bearer — `api/_auth.py`), 모델 `LLM_MODEL_LIGHT`.
- 입력: `[{who: 's1', mid, title, brief, define, pairs: [{q, a}]}]` — **학생 이름은 보내지 않는다**. 화면이
  s1… 을 이름으로 되돌린다. 한 요청 최대 40명 · 학생당 대화 최대 20쌍(최근 것).
  40명을 넘으면 최근에 끝낸 40명만 보내고 화면에 그렇다고 한 줄 적는다 (한 반 25명 안팎이라 나눠 보내기는 안 만든다).
- 출력: `{items: [{point, who: ['s1', …], mid, quote}]}` — 같은 지점에 막힌 학생을 한 항목으로 묶는다.
  학생 한 명 요청이면 who 가 하나인 같은 모양. 한 함수 · 한 스키마로 둘 다 처리한다.
- 결과는 강사 브라우저에만 캐시한다 (`js/data` 층, 키 = 반 + 대상 학생들 + 마지막 `s-tutor` 시각).
  튜터 대화가 새로 쌓이면 키가 바뀌어 다시 만들 수 있다. 반 전체 키는 반의 누구든 새 질문을 하면 바뀐다 —
  캐시는 비용 절약일 뿐이라 괜찮다. 서버 DB 저장은 하지 않는다.

### 화면 (`teacher.html` / `js/ui/teacher.js`)

- **학생별**: 학생 서랍(drawer)의 미션 블록에 "수업에서 짚을 거리" 행. 그 미션을 끝냈고 튜터 기록이 있을 때만
  버튼 "튜터 대화에서 뽑기". 결과는 항목마다 point 한 줄 + 접힌 근거 질문.
- **반 전체**: "튜터 기록 내려받기" 옆에 "수업에서 짚을 거리" 버튼. 끝낸 미션이 있는 학생 전원을 한 번에 보내고,
  항목을 묶음 학생 수가 많은 순으로 보여 준다. 항목을 펼치면 학생 이름 · 근거 질문. 많은 순 정렬은 수업에서
  먼저 짚을 것을 고르기 위한 것이고, 학생 순위가 아니다.
- 실패 · 시간 초과는 "지금은 뽑지 못했어요. 잠시 뒤 다시 눌러 주세요." 한 줄. 화면은 서버 없이도 열린다
  (버튼만 안 됨).

## 제약

- 정적 HTML/ES5, 층 규칙(core/data/ui), 번들러 · ES 모듈 없음. 새 이벤트 없음 (B 는 기존 `s-tutor`
  · `s-code-judge` 를 읽기만 한다).
- 서버 함수는 Vercel 30초 한도. recap 은 한 번 호출 + 형식 검사, 재시도 1회까지.
- 학생 자유 입력(질문 원문)이 교사 화면에 그대로 올라간다 → `test/robust.js` 경로에 recap 의 quote 표시를 더한다
  (textContent 만, innerHTML 금지).
- 비밀값 · 강사 비밀번호는 저장소 · 로그 · 문서에 쓰지 않는다. 실험은 헤드리스 브라우저.
- CLAUDE.md 의 아홉 테스트 + 새 `test_tutor_recap.py`(가짜 LLM) 통과 후 커밋.
