# 나침반 2차 — 체크리스트 · 최근 5개 가중 평균 · 상쇄되면 선생님이 고른다

2026-10-20 · 사람이 대화로 확정. 1차 설계(`2026-10-20-compass-design.md`)의 단계(0~3) 판정과 바늘 규칙을 바꾼다.
저장 · 권한 · 학생에게 안 가는 열 · 알림 한 번 · 생성 한도 미차감 같은 1차의 나머지는 그대로.

## 왜

- AI 가 단계를 고르면 같은 기록에도 흔들릴 수 있다. **예/아니오 항목**으로 쪼개면 결정적이다.
- 미션 하나로 방향을 정하면 들쭉날쭉하다. 학생의 방향은 **최근 미션들의 흐름**이다.
- 벡터가 상쇄되는 순간은 기계가 정할 근거가 없다. 그 판단은 **선생님이 한다** — 마침 칭찬 타이밍이다.

## 체크리스트 (방향마다 3개, 충족 개수 = 그 방향 점수 0~3)

| 방향 | 항목 | 판정 |
|---|---|---|
| 북 · 이해 | N1 함정이 아닌 성공 조건을 골랐다(골랐다가 스스로 바꾼 것 포함) | 코드 |
| | N2 성공 조건을 코드로 직접 옮겼다(코드가 성공 조건과 같은 것을 확인·출력) | AI |
| | N3 튜터에게 자기가 이해한 것을 설명하고 맞는지 물었다 | AI |
| 동 · 설계 | E1 설계 카드를 냈다 | 코드 |
| | E2 설계 이유를 자기 말로 적었다(보기 베끼기·"."·한 단어는 아니오) | AI |
| | E3 실행해 에러·반례가 나온 뒤 설계를 고쳤다 | 코드 |
| 남 · 구현 | S1 에러 없이 실행되는 코드가 있다 | 코드 |
| | S2 에러가 난 뒤 스스로 고쳐 다시 돌렸다(에러가 한 번도 없었으면 예) | 코드 |
| | S3 반례 자료까지 같은 코드로 돌렸고 하드코딩 신호가 없다 | 코드 |
| 서 · 검증 | W1 반례 자료를 직접 돌렸다 | 코드 |
| | W2 판정 근거를 실제 실행 결과에 기대어 적었다(출력값·자료를 말함) | AI |
| | W3 반례가 깨진 걸 보고 코드나 성공 조건을 고쳤다 | 코드 |

- AI 항목은 **예/아니오 하나 + 근거 인용**. 인용이 실제 기록(학생 문장·튜터 질문·코드)에 글자 그대로 없으면 아니오.
- 판정은 미션이 끝날 때(첫 `s-code-judge`) 한 번 하고 저장한다. "다시 읽기"만 다시 판정한다.
- 튜터 질문은 따로 **네 방향 중 하나로 분류**해 저장한다(이해: 요구·성공 조건 / 설계: 나누기·순서 / 구현: 문법·에러·코드 / 검증: 결과가 맞는지·반례). "답 알려줘"류는 분류 안 함. 분류는 **선생님이 볼 참고 자료**일 뿐 점수에 더하지 않는다.

## 누적 바늘 — 최근 5개 미션 가중 평균

- 미션마다 벡터 `x = E − W`, `y = N − S`(각 0~3 점수).
- 최근 미션부터 가중치 `1.0, 0.85, 0.7, 0.55, 0.4` (가장 오래된 것이 0.4). 미션이 5개보다 적으면 있는 만큼 같은 순서로.
  **가중치는 해 보면서 고친다** — 상수 하나(`WEIGHTS`)로 둔다.
- 누적 벡터 = Σ(가중치 × 벡터) / Σ가중치. 바늘 방향 = 각도, 바늘 길이 = 크기 비례(화면 반지름의 25~90%, 최소 25%로 늘 보이게).
- 방위 이름 = 바늘이 속한 90° 부채꼴(1차 규칙 그대로).
- 학생 문구: `○쪽으로 가고 있어요`, 바늘이 짧으면(크기 작음) `고르게 가고 있어요` 를 덧붙인다.
- 계산은 서버 코드가 저장된 체크 결과로 그때그때 한다. **방향 점수·평균은 저장하지 않는다**(원본 판정만 저장 → 계산식을 바꿔도 다시 계산).

## 상쇄되면 — 선생님이 고른다

- 누적 벡터 크기가 기준(`CANCEL = 0.5`, 해 보면서 조정) 미만이면 **자동으로 정하지 않는다.**
- 선생님에게 **칭찬 타이밍** 알림: `OO이 최근 미션에서 이해와 구현이 같이 두드러져요. 어느 쪽이 더 보였는지 골라 주세요.`
- 학생 상세 나침반 카드에 **겹친 후보만** 버튼으로: 북·남이 지워졌으면 북/남, 동·서면 동/서, 넷 다 같으면 넷. 옆에 두 후보의 ✓ 항목과 튜터 질문 분포를 참고로.
- 선생님이 고르고 한마디를 보내면 그 방향이 누적 바늘(정중앙 각도, 길이는 최소 길이). 선택은 그 미션 행에 저장 → 다시 계산해도 같다.
- 고르기 전에는 학생 누적 나침반을 바꾸지 않는다(직전에 보낸 상태 유지). 한 번도 보낸 적 없으면 `선생님이 곧 방향을 알려 주실 거예요.`
- 1차의 "길이 1 미만이면 바늘 숨김", "고르지 않음" 은 없앤다 — 바늘은 늘 하나의 방향을 가리킨다(상쇄 때는 선생님이 정할 때까지 이전 보낸 상태).

## 화면

- **학생**: "내 기록" 탭에 누적 나침반 하나(바늘 + 방위 + 짧은 설명). 미션별 카드는 바늘 없이 선생님 한마디만. 체크 항목·점수·난이도는 학생에게 절대 안 간다.
- **선생님**: 학생 상세에 누적 바늘 + 최근 5개 미션의 12칸 체크리스트(✓/–, 근거 인용) + 튜터 질문 분포. 상쇄면 후보 버튼. 미션별 한마디 보내기는 1차대로.
- 흑백 화면에서 방향 구분: 색 대신 방향별 모양(▲ 북 · ◧ 동 · ○ 남 · ◇ 서 — 시안으로 확정). 브랜드 색은 아이콘·로고에만, 고정.

## 저장

- `compass` 행(학생·미션): `checks jsonb {N1:{ok,quote}, …, W3}`, `tutor_dirs jsonb {N,E,S,W: 개수}`, `teacher_dir`(상쇄 때 선생님 선택 또는 미션 한마디의 방향), 1차 열 유지. 마이그레이션으로 열 추가, `levels`/`needle_deg` 는 계산값이라 더 이상 쓰지 않는다(지우지는 않음 — 운영 데이터).
- 학생 RPC 는 누적 결과(`needle_deg`, `dir`, `short`)와 미션별 `teacher_note` 만.

## 테스트

- 체크 항목별 코드 판정 단위 테스트, AI 항목 근거 대조, 가중 평균(미션 1~5개, 6개째는 빠짐), 상쇄 판정과 후보(북남 / 동서 / 넷), 선생님 선택 후 재계산 동일, 학생 RPC 에 체크·점수 없음.
