# 밤샘 작업 — 문제 생성 품질 · AI 튜터 · 교사 알림 · 파이썬 실행 보강

작성일 2026-10-16

## 1. 목표

아침에 아래가 손에 있으면 성공이다.

1. **문제 생성 품질이 eval 지표로 올라가 있다.** 성공 조건과 LLM이 정하는 값이 검사를 통과하고,
   학생이 보는 문장은 짧은 문제 형식이다.
2. **핵심 흐름이 끝까지 돈다.** 교사 문제 생성 → 학생 해결 → 설계도 → 파이썬 코드 → 완료.
   E2E 테스트 하나가 이 흐름 전체를 검증한다.
3. **코드 작성 단계에 AI 튜터가 있다.** 파이썬 문법만 답하고 정답 코드는 주지 않는다.
4. **교사가 알림을 받는다.** 설계도 제출과 코드 완성 시점.
5. **파이썬 실행이 학생 코드에 깨지지 않는다.** 무한루프, `input()`, 로드 실패.
6. **아침 리포트**가 결과와 사람이 판단할 것을 정리해 둔다.

**하지 않는 것:** 디자인 변경(후순위), push·PR, LLM 제공자 교체, 점수·순위·소요 시간 표시.

## 2. 실행 방식

세션 하나가 이 스펙에서 나온 구현 계획을 따라가고, 작업마다 서브에이전트를 띄운다
(`superpowers:subagent-driven-development`). 메인 세션은 결과만 받아 컨텍스트를 작게 유지한다.

거절한 선택지:
- Workflow 병렬 실행 — 작업들이 `sentence.js`·`teacher.js` 를 공유해 동시 수정 충돌이 난다.
- 셸 루프로 작업마다 `claude -p` 재시작 — 작업 간 맥락이 끊긴다.

### 2.1 컨텍스트 관리

- 컨텍스트 60% 에서 자동 압축: 세션을 `claude --autocompact 600k` 로 띄운다 (1M 의 60%).
- 사용량: `teamclaude run` 으로 띄운다. 프록시가 사용량 98% 에서 다른 계정으로 넘긴다.
  한도 에러가 나면 `teamclaude switch <다른 계정>`, 두 계정 모두 한도면 리포트를 쓰고 멈춘다.
- 슬래시 명령(`/compact`)은 사용자 입력으로만 실행되므로 세션이 스스로 부르지 않는다.

### 2.2 운영 규칙

- 작업이 끝날 때마다 **기존 테스트 6개 + Python 테스트 + 새 테스트 전부 통과 → 커밋.**
  커밋 메시지는 CLAUDE.md 규칙대로 "왜"와 "거절한 선택지"를 적는다.
- 작업 하나가 **수정 3회 시도 후에도 테스트 실패**면 마지막 커밋으로 되돌리고,
  리포트에 사유를 적고 다음 작업으로 넘어간다.
- 로컬 브랜치에만 커밋한다. **push·PR 금지.**
- 다른 세션이 쓰는 워크트리(`coho` 등)의 파일은 작업 0의 확인 절차 외에는 건드리지 않는다.
- 문제가 생기면 `docs/트러블슈팅.md` 를 먼저 찾고, 없으면 해결한 뒤 확인된 해결법만 추가한다 (CLAUDE.md "문제가 생기면").
  리포트의 "사람이 판단할 것"에 그날 추가된 항목을 적는다.

### 3.2 작업 1 — 핵심 흐름 E2E 기준선

`test/e2e-flow.spec.js` (Playwright, 기존 `playwright.config.js` 사용).

1. 교사 화면에서 미션 생성 (LLM 호출은 고정 응답으로 대체 — 테스트가 API 키와 비용에 묶이지 않게)
2. 교사가 확정 → 학생 화면에 그 미션이 뜸
3. 학생이 성공 조건 선택 → 방법 문장 빈칸 선택 → 설계도 제출
4. 코드 작성 단계에서 파이썬 코드 입력 → 실행 → 결과 판정
5. 마무리 → 완료
6. 교사 화면에 설계도와 코드가 보임

이 시점엔 3~6번이 실패해도 된다. **어디서 깨지는지 기록하는 게 목적이다.**
알림·튜터 단계는 작업 3·4에서 이 스펙 파일에 추가한다.

반복: 프롬프트·스키마·검사기 수정 → `test/eval_generate.py` → 이전 회차와 비교 → 커밋.

|---|---|---|
| 미션 생성 성공 | 7 / 10 | 9 / 10 |

| 기본 틀로 바뀐 칸이 없는 미션 | 0 / 10 | 6 / 10 |

종료: 세 목표 모두 도달, 또는 **eval 20회**(약 600 LLM 호출) 소진. 못 미치면 다음 작업으로 넘어간다.

먼저 볼 곳 (eval v2 기준):
- `sentences` 실패 14회 — template 에 `{slot}` 이 빠지거나 문장이 지시문("명시하세요")이 됨
- 실패한 3개 주제 — 숫자 형변환·예외 처리·파일 입출력 (`split-num-sum`, `split-filter-num-sum`, `split-filter-count`)

**학생 문장 규칙** (검사기에 있는 것은 유지, 없는 것은 추가):
- brief 40자, situation 30자, 각 칸 한 문장
- 문제 형식: 학생에게 일을 맡기는 요청문. 설명문·지시문("명시하세요", "확인하세요") 금지
- 중1이 모를 단어 금지: `로직`, `데이터`, `타당성`, `집계`, `카운터` 같은 개발 용어
- 답 암시 금지, 방법이 적힌 성공 조건 금지 (기존 규칙)

eval 은 지표 숫자만 보지 않는다. 회차마다 생성된 미션 3개를 골라 리포트에 원문 그대로 붙인다 —
숫자는 올랐는데 문장이 이상해지는 경우를 아침에 사람이 볼 수 있게.

**금지:** 지표를 올리려고 검사기를 느슨하게 만드는 것. 검사 규칙을 바꿨다면 커밋 메시지와 리포트에
무엇을 왜 바꿨는지 적는다.

## 5. AI 튜터

### 5.1 어디서, 언제

- `sentence.html` 의 **코드 작성 단계에서만** 오른쪽 아래 버튼 "파이썬 문법 물어보기".
  설계도 제출 전에는 버튼이 없다.
- 누르면 문의창 같은 모달: 질문 입력 → 답변 → 대화가 이어짐. 닫았다 열어도 대화가 남는다.
- **횟수 제한 없음.**
- 말투는 존댓말. 반말 예외는 되묻기(`js/core/asks.js`)에만 둔다.

### 5.2 흐름

```
학생 질문 → POST /api/tutor { question, missionId, code }
  ① 분류 (LLM, structured output): syntax | solution_request | off_topic
  ② syntax 만 답변 생성. 나머지는 고정 거절 문장
  ③ 답변 검사 (코드) → 실패 시 1회 재요청 → 그래도 실패면 고정 거절 문장
  ④ 응답 → 화면 → 이벤트 s-tutor { question, answer, refused } 기록
```

파일: `api/tutor.py` (핸들러), `api/_tutorguard.py` (검사), `js/ui/tutor.js` (모달).
LLM 호출은 `api/_generate.py` 의 호출 함수와 `PICKLE_API_KEY` 를 재사용한다.

### 5.3 답변 검사 — 막는 것

- 이 미션의 자료 값이나 미션 고유 단어(제목·itemName)가 답에 들어감
- 코드 예시가 **2줄 이상**이거나 `print` 로 결과까지 내는 완성 프로그램
- 학생 코드를 고쳐서 돌려주는 것
- 방법 판단("여기선 중복을 빼야 해요") — 설계도에서 학생이 이미 내린 판단이다
- 칭찬, 반말, `너` (기존 `llmguard.js` 규칙과 같은 기준)

허용: 미션과 다른 자료로 된 **한 줄 예시 + 짧은 설명**. 답변 200자 이내.

### 5.4 거절 문장 (고정)

- 정답 요청: "코드는 직접 써 보는 거예요. 궁금한 문법이 있으면 물어봐 주세요."
- 범위 밖: "파이썬 문법 질문만 받을 수 있어요."
- 서버 없음: "지금은 튜터를 쓸 수 없어요." — 모달은 열리고 수업 흐름은 막지 않는다.

### 5.5 기록과 교사 화면

- `js/core/events.js` 에 `S_TUTOR: 's-tutor'`, `fold.js` 에 case 추가.
- 교사 화면 학생 상세에 질문과 답을 **그대로** 보여준다 (자유 입력은 교사 화면에 올린다는 규칙).
- `test/robust.js` 에 튜터 질문 → 교사 화면 경로를 추가한다.

### 5.6 테스트

`test/test_tutorguard.py` — 막아야 할 사례를 통과시킬 사례보다 많이:
정답 코드, 자료 값 포함, 여러 줄 코드, 학생 코드 수정본, 방법 판단, 반말, 칭찬.

## 6. 교사 알림

- 새 이벤트 없음. `s-design`(설계도 제출)과 `s-code-judge`(학생이 코드 결과를 판정 = **코드 완성**)를 쓴다.
- 비교 함수 `CC.alerts.diff(prev, next)` 를 `js/core/alerts.js` 에 순수 함수로 둔다.
  직전 fold 결과와 비교해 새로 생긴 설계도 제출·코드 완성만 돌려준다.
- 교사 화면은 지금 교실을 고를 때 한 번만 기록을 읽는다(`teacher.html` `loadStudentEvents`).
  Supabase 모드는 5초 폴링, 로컬 모드는 브라우저 `storage` 이벤트로 갱신을 더한다.
- 갱신 때마다 diff → 오른쪽 위 토스트 "3번 자리가 설계도를 냈어요." (5초 후 사라짐)
  + 대시보드 상단 "최근 알림" 목록 (최근 10개, 시간순).
- **처음 열었을 때 이미 있던 제출은 알리지 않는다.** 새로고침마다 알림이 쏟아지지 않게.
- **띄우지 않는 것:** 순서("첫 번째로"), 소요 시간, 판정 결과(지켰다/못했다).
- 테스트: `layer.test.js` 에 diff 사례 (첫 로드, 새 설계도, 새 코드 완성, 같은 학생 반복 판정).

## 7. 파이썬 실행 보강

지금은 `sentence.js:381` 에서 `runPython` 을 메인 스레드에서 동기로 실행한다.
`runPython` 은 파이썬이 끝날 때까지 돌아오지 않으므로 `while True:` 하나에 탭 전체가 멈추고,
자바스크립트에는 실행 중인 코드를 밖에서 끊을 방법이 없다.
기록(`rec('s-code')`, `sentence.js:402`)이 실행 **뒤에** 있어서 멈추게 만든 코드는 기록되지 않는다.
이전 기록은 `store.js` 가 `localStorage` 에 이미 저장해 두므로 남는다.

| 문제 | 수정 |
|---|---|
| 무한루프 | Pyodide 를 Web Worker(`js/ui/pyworker.js`)로 옮기고 5초 뒤 `terminate()`. "5초 안에 끝나지 않아서 멈췄어요." 후 worker 재생성 |
| 멈춘 시도가 기록 안 됨 | Worker 시간 초과가 결과("5초 안에 끝나지 않아서 멈췄어요.")로 돌아오므로 기존 `s-code` 를 실행 후 기록해도 빠지지 않는다. 교사 화면에 보인다 |
| `input()` | "이 화면에서는 `input()`을 쓸 수 없어요. 자료는 `data`에 들어 있어요." |
| CDN 로드 실패 | 실행 버튼을 끄고 사실만 표시. 설계도·코드 입력·기록은 계속 된다 |
| 영어 traceback | 마지막 줄 + 줄 번호만: "3번째 줄: NameError …". 원인 해석 없음 |

`file://` 에서 Worker 가 막히면 지금처럼 메인 스레드 실행으로 내려간다 (타임아웃 없음). 오프라인 우선 원칙.

새 이벤트 type 은 만들지 않는다. `s-code` 의 의미가 바뀌지 않으므로 스키마 버전도 그대로다.
거절: Pyodide `setInterruptBuffer` — `SharedArrayBuffer` 가 COOP/COEP 헤더를 요구해 정적 호스팅에서 못 켠다.
