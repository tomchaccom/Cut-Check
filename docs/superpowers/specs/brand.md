# KOMPAS 브랜드 · UI 설계 레퍼런스

> 이 문서는 KOMPAS 서비스의 브랜드 정의, 역량 방향 체계, UI 콘셉트, 아이콘 제작 가이드를 한곳에 모은 레퍼런스입니다. 설계 문서를 작성할 때 이 내용을 기준으로 삼습니다. **(제안)** 표시가 붙은 항목은 확정 전 초안이므로 설계 과정에서 조정할 수 있습니다.

---

## 1. 브랜드 개요

### 1.1 서비스 한 줄 정의

KOMPAS는 학생의 문제 풀이 역량을 동·서·남·북 네 방향으로 진단하고, 지금 어느 방향으로 성장해야 하는지 알려주는 학습 피드백 서비스입니다.

### 1.2 이름의 의미

나침반은 목적지를 알려주지 않고 오직 방향만 가리킵니다. KOMPAS는 학생이 최종적으로 어디에 도달할지 정해주지 않지만, 지금 어느 쪽으로 나아가야 하는지는 분명히 알려줍니다. 또한 나침반 바늘은 사용자가 어디에 서 있든, 길이 어떻게 바뀌든 항상 같은 쪽을 가리킵니다. 이는 "계획은 바뀌어도 의도는 흔들리지 않는다"는 서비스 철학으로 이어집니다.

### 1.3 표기 원칙

공식 표기는 **KOMPAS**입니다. 영어 표기는 COMPASS이며, KOMPAS는 인도네시아어·네덜란드어·폴란드어 등에서 쓰는 표기입니다(독일어는 KOMPASS). 영어 COMPASS는 너무 흔한 일반 단어라 묻히기 쉬운 반면, KOMPAS는 누구나 나침반임을 알아보면서도 철자가 살짝 낯설어 고유한 이름처럼 보인다는 장점 때문에 의도적으로 K 표기를 선택했습니다.

주의할 점으로, KOMPAS는 여러 언어에서 일반 명사이고 인도네시아의 대형 언론사 이름이기도 해서 검색 노출이나 도메인·핸들 확보가 어려울 수 있습니다. 이 경우 `kompas.dev`처럼 접미사를 붙이거나 KOMPASS, KOMPA 등으로 변형하는 방안을 검토합니다.

### 1.4 네이밍 배경

"의도를 코드로 옮긴다"는 문장에서 출발했습니다. 계획을 완벽히 세우지 않고 시작하더라도 방향만은 잃지 않는다는 의미를 담고 싶었고, 등산 장비 아이젠처럼 실제 도구 이름에서 따오는 방식을 참고해 나침반을 최종 선택했습니다.

## 2. 브랜드 메시지

| 용도 | 문구 |
|---|---|
| 메인 슬로건 | 의도를 코드로 옮긴다 |
| 서브 슬로건 | 목적지는 몰라도, 방향은 안다. |
| 대안 서브 슬로건 | 지도는 없어도 방향은 있다. |
| 영문 슬로건 | Direction before destination. |
| 결합형 | KOMPAS — 의도를 코드로 옮긴다 |

핵심 메시지는 **계획(지도)과 의도(방향)의 대비**입니다. 지도가 없어도, 즉 계획이 완벽하지 않아도 방향이 있으면 나아갈 수 있다는 것이 KOMPAS가 학생에게 전하는 메시지입니다.

## 3. 역량 방향 체계

### 3.1 4방위 정의

| 방향 | 역량 | 정의 | 의미 부여 | 대표 색상 |
|---|---|---|---|---|
| 북 (N) | 문제 이해 | 문제가 무엇을 요구하는지, 조건과 제약을 정확히 파악하는 능력 | 북극성처럼 모든 풀이의 기준점 | Indigo `#4F46E5` |
| 동 (E) | 설계·전략 | 접근법을 세우고 자료구조, 알고리즘, 복잡도를 판단하는 능력 | 해가 뜨는 쪽, 아이디어의 시작 | Amber `#F59E0B` |
| 남 (S) | 구현 | 설계를 정확한 코드로 옮기는 능력 | 의도를 실제 코드로 옮기는 단계 | Teal `#14B8A6` |
| 서 (W) | 검증·회고 | 엣지 케이스 테스트, 디버깅, 풀이를 돌아보는 능력 | 해가 지는 쪽, 하루의 마무리 | Coral `#FB7185` |

문제 풀이 흐름인 **이해 → 설계 → 구현 → 검증**은 나침반 위에서 **북 → 동 → 남 → 서**, 즉 시계 방향으로 한 바퀴를 도는 구조입니다. 한 문제를 푸는 과정이 나침반을 한 바퀴 도는 것과 같다는 스토리로 활용할 수 있습니다.

### 3.2 방향별 피드백

| 방향 | 부족할 때 나타나는 신호 **(제안)** | 피드백 |
|---|---|---|
| 북 (N) 문제 이해 | 문제를 잘못 이해해 엉뚱한 답을 냄, 조건 누락 | 문제를 한 줄로 재진술하기, 입출력 예시 직접 만들어보기 |
| 동 (E) 설계·전략 | 생각 없이 바로 코딩 시작, 시간 초과가 잦음 | 코드 쓰기 전 접근법 3줄 적기, 시간복잡도 먼저 계산하기 |
| 남 (S) 구현 | 아이디어는 맞는데 코드로 못 옮김, 인덱스·문법 실수 | 의사코드 먼저 쓰기, 자주 쓰는 패턴 템플릿화하기 |
| 서 (W) 검증·회고 | 예제는 맞는데 제출하면 오답, 같은 실수 반복 | 엣지 케이스 테스트 습관, 오답 노트로 회고하기 |

### 3.3 사이 방위 해석 **(제안)**

두 방향이 함께 약할 때는 사이 방위로 해석해 더 구체적인 피드백을 줄 수 있습니다.

| 방위 | 조합 | 해석 | 피드백 방향 |
|---|---|---|---|
| 북동 (NE) | 이해 + 설계 | 코드에 손대기 전 단계가 약함 | 풀기 전에 생각하는 시간을 의도적으로 확보하기 |
| 남동 (SE) | 설계 + 구현 | 아이디어를 코드로 연결하는 구간이 약함 | 설계 → 의사코드 → 코드로 단계적으로 옮기기 |
| 남서 (SW) | 구현 + 검증 | 풀이의 완성도와 마무리가 약함 | 작은 단위로 구현하고 바로 테스트하기 |
| 북서 (NW) | 검증 + 이해 | 요구사항을 다시 확인하는 습관이 약함 | 제출 전에 문제 조건과 내 답을 다시 대조하기 |

## 4. UI 콘셉트

### 4.1 핵심 시각화

학생의 4방향 역량 점수를 나침반 위에 레이더 차트처럼 다각형으로 그립니다. 나침반 바늘은 **다음에 가야 할 방향, 즉 가장 보완이 필요한 쪽**을 가리킵니다. 이렇게 하면 "어디로 갈지는 몰라도 방향만은 알려준다"는 브랜드 메시지가 UI에서 그대로 구현됩니다.

### 4.2 바늘 방향 결정 로직 **(제안)**

각 방향의 점수를 0~100으로 산출한다고 가정합니다. 기본적으로 바늘은 점수가 가장 낮은 방향을 가리킵니다. 인접한 두 방향(예: 남과 서)이 모두 기준 점수(예: 60점) 미만이고 둘의 점수 차가 작다면(예: 10점 이내), 바늘은 그 사이 방위(예: 남서)를 가리킵니다. 마주 보는 두 방향(북과 남, 동과 서)만 약한 경우에는 더 낮은 쪽을 가리킵니다. 모든 방향이 기준 이상인 "균형" 상태에서는 바늘이 최저 방향을 가리키되, 기초 보완이 아닌 심화 피드백을 보여줍니다. 위 수치는 모두 예시이며 실제 데이터를 보고 조정합니다.

### 4.3 결과 화면 구성 **(제안)**

| 영역 | 내용 |
|---|---|
| 상단 | 나침반 레이더와 바늘, 현재 방위 라벨 (예: "남서쪽으로 가보세요") |
| 중단 | 바늘이 가리키는 방향의 피드백 카드를 가장 먼저 노출 |
| 하단 | 4방향 각각의 상세 점수와 피드백 카드 (탭 또는 카드 목록) |
| 성장 기록 | "항해 일지": 시간에 따라 레이더 모양과 바늘 방향이 어떻게 바뀌었는지 보여주는 기록 화면 |

### 4.4 UI 문구 톤 **(제안)**

"틀렸다"보다 "이쪽으로 가보자"는 안내의 톤을 사용합니다. 학생을 평가하기보다 다음 한 걸음을 제안하는 말투입니다.

예시: "지금은 서쪽이 비어 있어요. 제출 전에 엣지 케이스를 하나만 더 확인해볼까요?"

## 5. 비주얼 아이덴티티

### 5.1 컬러 시스템

| 용도 | 색상 | HEX |
|---|---|---|
| 배경 / 브랜드 기본 | Dark Navy | `#0F172A` |
| 북 (N) 문제 이해 | Indigo | `#4F46E5` |
| 동 (E) 설계·전략 | Amber (일출) | `#F59E0B` |
| 남 (S) 구현 | Teal | `#14B8A6` |
| 서 (W) 검증·회고 | Coral (노을) | `#FB7185` |

UI 레이더 차트와 피드백 카드에 모두 같은 색상 매핑을 사용해 브랜드 일관성을 유지합니다. 색만으로 방향을 구분하지 않도록 UI에서는 항상 방위 라벨이나 역량 이름을 함께 표기합니다(접근성).

### 5.2 아이콘 콘셉트

핵심은 **목적지 없는 방향**입니다. 지도나 위치 핀 같은 "도착지"를 암시하는 요소는 넣지 않고, 나침반의 4방위와 바늘만으로 구성합니다. 바늘은 북동쪽을 향해 상승하고 전진하는 느낌을 줍니다.

**아이콘 색은 노랑 `#FFD400` · 흰 `#FFFFFF` · 검정 `#000000` 세 색뿐입니다(2026-10-21).** 노란 바탕 · 검은 4방위 · 검은 테두리의 흰 바늘(북동). 그라디언트 · 회색 · 반투명 중간색은 쓰지 않습니다. 네 역량 색을 끝마다 칠했던 첫 안은 16px 에서 네 색이 한 점으로 뭉개졌고, 노란 타일은 라이트 · 다크 어느 배경에서도 한눈에 찾힙니다. 역량 색(5.1)은 화면 속 나침반 카드에만 씁니다.

### 5.3 아이콘 제작 프롬프트

이미지 생성 AI는 영어 프롬프트를 더 잘 따르는 경향이 있어 영어로 작성했습니다.

**메인 프롬프트**

```
A minimalist app icon for "KOMPAS", an education service that guides
students' problem-solving growth. A clean geometric compass rose with
four cardinal points, each tinted a distinct accent color: North in
deep indigo, East in warm amber (sunrise), South in teal, West in soft
coral (sunset). A single sleek needle in the center points toward the
north-east, suggesting direction without a destination: no map, no
location pin. Flat vector style, dark navy rounded-square background
with a subtle gradient, generous padding, high contrast, centered
composition, readable at small sizes from 16px to 1024px. Modern,
calm, trustworthy. No text.
```

**변형 A: K를 품은 나침반**

```
Same concept, but the compass needle is formed by the diagonal strokes
of a stylized letter "K", so the letter and the needle read as one
shape. Minimal, clever, monogram-like.
```

**변형 B: 코드 느낌을 더한 버전**

```
Same concept, but the needle tip is shaped like a chevron ">" or a
blinking text cursor, hinting that intent turns into code.
```

**네거티브 프롬프트 (지원하는 도구에서 사용)**

```
text, letters N E S W, map, location pin, realistic metal, 3D
skeuomorphism, heavy shadows, clutter, thin hairlines, photorealism
```

### 5.4 제작 가이드

이미지 생성 AI는 글자를 정확히 그리지 못하는 경우가 많으므로 아이콘 안에는 텍스트를 넣지 않고, KOMPAS 워드마크는 별도로 제작합니다. 생성된 이미지는 가장자리가 깔끔하지 않을 수 있으니 마음에 드는 시안을 고른 뒤 Figma 등에서 벡터로 다시 그려 정리합니다. 벡터화된 나침반 도형은 앱 아이콘, 파비콘, UI 속 레이더 차트 배경까지 같은 형태로 재사용합니다. 최종 아이콘은 16px, 32px, 512px, 1024px 크기에서 모두 알아볼 수 있는지 확인합니다.

## 6. 결정이 필요한 사항

| 항목 | 내용 |
|---|---|
| 서비스 대상 범위 | 현재 방향 체계는 코딩 문제 풀이를 기준으로 정의되어 있음. 일반 교과 문제로 확장할 경우 남쪽(구현)을 "풀이 전개"로 일반화하는 등 정의 조정 필요 |
| 역량 측정 방식 | 4방향 점수를 무엇으로 산출할지 결정 필요 (문제 풀이 로그, 제출·채점 결과, 자가 진단, 교사 평가 등) |
| 바늘 로직 수치 | 기준 점수, 사이 방위 판정 점수 차 등 임계값 확정 |
| 아이콘 최종안 | 메인 / 변형 A / 변형 B 중 선택 |
| 상표 확인 | KIPRIS에서 KOMPAS 및 변형 표기 상표 등록 여부 확인 |
| 도메인·핸들 | 도메인, 깃허브 조직명, SNS 핸들 확보 가능 여부 확인 |
