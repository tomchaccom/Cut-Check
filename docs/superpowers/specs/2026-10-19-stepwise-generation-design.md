# 단계별 미션 생성 — 개념 → 스토리 고르기 → 만들기 → 확인

2026-10-19 · 사람과 브레인스토밍한 결과. 짝 문서: `2026-10-19-student-code-facts-design.md`.

## 왜

지금 생성기는 수업 내용을 받아 한 번에 미션을 만든다. 두 가지가 계속 문제였다.

1. **강사가 고를 수 없다.** 결과가 마음에 안 들면 처음부터 다시 돌릴 뿐이다. 이야기가 억지스럽거나("민지가 간식 이름이 몇 번 나왔는지") 수업 개념과 어긋나도 손댈 곳이 없다.
2. **엔진이 split 으로 시작하는 14개 틀만 안다.** for/while/if(숫자 비교)/함수 수업이 들어와도 결국 split 문제로 바뀐다. 설문 검증(`scratchpad/survey-check/report.md` C8)에서 for 수업 → 반복 없이 풀리는 split 문제, if 수업 → 기준 점수 없는 명단 일치 문제가 나왔고 둘 다 검수를 통과했다.

사람의 말: "문제 생성 전. 파이썬 개념 확인 → 파이썬 개념 기반의 중학생이 쉽게 이해가능한 스토리 구조 예시 목록 강사에게 제시 → 강사가 선택한 내용 + 수정되었으면 하는 내용(강사 입력)으로 문제 재생성 및 보강 → 생성된 문제 확인."

## 흐름 (사람이 정함)

1. **개념 확인** — 강사가 지금처럼 "오늘 배운 것 / 핵심"을 적으면 AI 가 이 수업의 파이썬 개념을 하나 짚는다. 강사는 그대로 두거나 바꾼다.
2. **스토리 예시 목록** — 그 개념을 꼭 써야 풀리는, 중학생이 바로 이해하는 생활 소재 예시 여러 개. 강사가 하나를 고른다.
3. **만들기** — 고른 예시 + 강사가 적은 "이렇게 바꿔 줬으면" 문장으로 미션 전체를 만든다(재생성·보강).
4. **확인** — 만들어진 미션을 강사가 보고 고치고 확정한다. 자료마다 정답이 보인다(사람: "정답은 강사가 봐도 돼").

## 예시 목록의 모양 (사람이 정함)

사람이 고른 기준: **짧아야 한다**("설명이 너무 긴 것들은 나도 읽기 싫어서 별로"), **현실적**("1번 현실적임"), **쉬움**("2번 예시 쉬움").
브레인스토밍에서 보여 준 꼴을 사람이 "문제 다 괜찮다"고 했다. 예시 하나 = 세 줄을 넘지 않는다:

```
매점 영수증 — 오늘 산 간식 가격이 목록으로 있어요. 모두 얼마 썼는지 알아내요.
→ 하나씩 꺼내서 더해 가기
```

- 제목(짧은 명사) · 상황 한 줄(학생 존댓말, 40자 안팎) · `→` 이 소재에 이 개념이 왜 필요한지 한 줄.
- 지난 개념이 함께 들어가면 `→` 줄에 드러낸다(예: `하나씩 보며 조건 맞으면 세기 (for + if)`).
- 한 번에 4~5개. "다른 예시 더 보기"로 새 묶음을 받을 수 있다.

개념별 참고 예시(사람이 다 괜찮다고 한 목록 — 프롬프트 예시로 써도 된다):

| 개념 | 예시 |
|---|---|
| 문자열 나누기 | 급식 메뉴판(반찬 몇 가지), 카톡 닉네임 모음(세 번째 친구) |
| 리스트·인덱스 | 버스 도착 순서(마지막 버스), 시간표(4교시 과목) |
| if | 놀이기구 키 제한(140 이상), 수행평가 통과(60 이상) |
| for | 매점 영수증(합계), 줄넘기 일주일(100번 넘긴 날 수) |
| while | 용돈 모으기(몇 주), 게임 체력(몇 대 맞으면 0 이하) |
| 딕셔너리 | 단톡방 투표(메뉴별 표), 포켓몬 도감(이름 → 타입) |
| 집합 | 둘 다 가능한 시간(교집합), 출석 체크(겹친 이름 빼고 몇 명) |
| 함수 | 배달비 계산기, 학점 바꾸기 |

## 정답을 어떻게 얻나 — 모범 답안을 실행한다 (사람이 받아들인 방식)

14개 틀을 계속 늘리는 길(A)은 버렸다: 강사가 while 소재를 골라도 split 문제가 나오는 문제가 그대로 남고, 개념마다 JS·Python 두 벌을 손으로 맞춰야 한다.

고른 길(B): **AI 가 문제·자료·모범 답안 코드를 함께 쓰고, 모범 답안을 자료마다 실제로 돌려 나온 값을 정답으로 삼는다.** AI 가 머리로 셈한 숫자는 정답이 되지 않는다.

### 어디서 돌리나 — 강사 브라우저 (리뷰 후 결정, 내 판단)

**모범 답안은 서버가 아니라 강사 화면의 Pyodide 에서 돌린다.** 학생 화면이 이미 쓰는 실행기(`js/ui/pyworker.js` + `sentence.js` 의 시간 제한·worker 재시작 방식)를 강사 화면에서도 쓴다.

왜 서버가 아닌가 (적대적 리뷰 B1·B2):
- Vercel 함수에서 자식 프로세스는 `/proc/<부모>/environ` 으로 `SUPABASE_SERVICE_ROLE_KEY`·`PICKLE_API_KEY` 를 읽을 수 있고 네트워크도 열려 있다. 빈 환경변수로는 못 막는다.
- "강사만 부를 수 있다"는 경계가 못 된다 — 이메일로 가입하면 누구나 강사다.
- 강사의 "이렇게 바꿔 줬으면" 입력으로 프롬프트를 주입하면 모범 답안이 키를 출력하고, 그 출력이 정답으로 `missions.data` 에 저장돼 학생에게 간다.
- "자료 고치면 다시 실행"은 아무 코드나 실행하는 창구가 된다(HMAC 서명이 필요해진다).

강사 브라우저에서 돌리면 서버는 LLM 만 부르고 코드를 실행하지 않는다. 브라우저 worker 안에는 서버 비밀이 없다. 자료를 고친 뒤 다시 계산하는 것도 그 자리에서 한다.

남는 위험과 처리:
- 모범 답안이 이상한 값을 출력해도 그건 강사 본인 화면이다. 그래도 **출력은 짧은 값만 받는다**(한 줄, 200자 이내, 비면 탈락) — 자료별 정답 칸이 곧 학생 브라우저로 가므로.
- 무한 반복·무거운 코드는 지금 학생 실행기와 같은 시간 제한(5초) + worker 재시작.
- Pyodide 로딩(처음 한 번 수 초)은 1단계를 하는 동안 미리 불러 둔다.

### 기계가 확인하는 것 (하나라도 걸리면 이유를 붙여 다시 만든다, 최대 2번)

검사 규칙은 **core 의 순수 함수 하나**(예: `js/core/solcheck.js`)에 둔다. 입력은 미션 초안 + 자료별 실행 결과 + 모범 답안의 문법 요약, 출력은 걸린 이유 목록. 짝 문서(학생 코드 사실)도 같은 개념 표를 쓴다 — 개념 규칙은 이 한 곳에만.
- 에러 없이 끝난다 · 시간 안에 끝난다
- 모범 답안이 고른 개념을 실제로 쓴다 — 개념 표(core): 개념 키 → 있어야 하는 파이썬 `ast` 노드 종류(예: while → `While`, for → `For` 또는 컴프리헨션, if → `If` 또는 `IfExp`, 함수 → `FunctionDef`, 딕셔너리 → `Dict`/`DictComp` 또는 `dict(` 호출, 집합 → `Set`/`SetComp` 또는 `set(` 호출, 리스트·인덱스 → `Subscript`, 문자열 나누기 → `.split(` 호출). 문법 요약은 Pyodide 에서 `ast.walk` 로 노드 이름 집합을 뽑는다.
- 반례(마지막 자료)의 답이 자료 1의 답과 다르다
- 출력이 한 줄·짧은 값이다
- 요청과 답의 꼴이 맞는다("몇"을 물으면 숫자)
- 학생이 읽는 문장(제목·상황·요청·카드·성공 보기·함정 문장)은 지금 학생 문구 검사를 통과한다(`api/_schema.py` 의 규칙, `js/core/llmguard.js`). 이제 성공 보기의 진짜 문장도 `_generate.py` 의 `CORRECT` 표가 아니라 AI 가 쓰기 때문.

다시 만들기 요청은 브라우저가 걸린 이유를 붙여 3단계 API 를 다시 부르는 것(서버는 같은 action).

### 기계가 못 잡는 것

"넘을 때까지"라 써 놓고 `<` 로 짠 것 같은 뜻의 어긋남은 두 겹:
- **따로 풀어 맞춰 보기** — 별도 API action(`gpt-5.4-mini`)에 모범 답안을 보이지 않고 문제와 자료만 주어 풀이 코드를 받고, 브라우저가 그 코드도 돌린다. 답이 다르면 4단계 화면에 "따로 푼 답과 달라요: 자료 2 — 4 / 5" 처럼 사실로 띄운다. 자동 탈락은 아니다. **초안이 화면에 뜬 뒤 따로 부른다** — 한 함수 호출 60초 안에 만들기·풀기·다시 만들기를 다 넣을 수 없다(리뷰 M5: LLM 호출당 최대 13초).
- **강사 확인** — 4단계에서 자료별 정답을 나란히 본다.

### 반례 규칙

CLAUDE.md 의 반례 네 축(개수 변화 / 구분자 변화 / 빈 결과 / 보이지 않는 차이) 중 새 꼴에 맞는 것은 **개수 변화 · 빈 결과**다(숫자 목록·while 소재에는 구분자·공백 축이 안 맞는다). **경계값 축을 더할지는 사람 결정 — 아래 '사람에게 물을 것'.** 자동 구현 중에 CLAUDE.md 를 고치지 않는다.
## 학생 쪽 미션 꼴

새 미션은 `pipelineId` 대신 `kind: 'code'` 를 단다. 학생 화면 흐름(01 문제 → 02 성공 조건 → 03 설계 카드 → 04 코드·판단 → 05 정리)은 그대로다.

- **자료 (리뷰 B3, 내 판단)**: 변수는 **`data` 하나**. `inputs[].v` 는 **한 줄짜리 파이썬 리터럴을 담은 문자열**(예: `"[1500, 800, 2000]"`, `"{'주급': 3000, '가격': 20000}"`, `"'떡볶이,우동'"`). `v` 가 문자열이라 지금 코드 — 강사 서랍의 `x.v === val`(`teacher.js`), 정리 화면 `lastResults`, 이벤트 `dataId` — 가 그대로 돈다. 여러 값이 필요하면 한글 키 딕셔너리(`{'주급': 3000, '가격': 20000}`)를 쓴다(중1이 읽기 쉽다).
  - 지금 `sentence.js` 는 자료 줄을 `/^data = ".*"/m` 로 찾고 값을 따옴표로 감싼다(418·420·423–425·436·467–469). 리터럴 자료는 이 정규식에 안 걸려서, 학생이 반례를 골라도 코드 속 자료 1 줄이 덮어써 늘 자료 1로 돈다. **core 에 자료 줄 만드는 함수 하나 + 자료 줄 찾는 정규식 `^data = .*$` 하나**를 두고 모든 곳이 쓰게 한다: 예전 미션은 `'data = ' + JSON.stringify(v)`, 새 미션은 `'data = ' + v`. 467줄의 백슬래시 미이스케이프 기존 버그도 같이 사라진다.
  - 튜터에 넘기는 자료(`sentence.js:41` 근처, 쉼표로 쪼갠다고 가정)는 새 꼴이면 `v` 를 그대로 넘긴다.
- **설계 카드 (리뷰 M7)**: `CC.cards.forMission(m)` 은 `m.cards` 가 있으면 그걸 쓴다(없으면 지금처럼 pipelineId). AI 가 단계 카드 3~5장(짧은 명사형) + 헷갈리는 카드 1장(`decoy: true`)을 쓰고 강사가 4단계에서 고친다. 세부 선택(detail)은 없다. 가나다순, 정답 순서 대조 없음은 그대로. `fixedList`·`s-method` 처럼 pipelineId 를 읽는 곳은 새 꼴에서 비어도 깨지지 않게.
- **성공 조건 보기**: 지금처럼 함정을 섞는다. `hardcode` 함정 문장은 실행한 자료 1 정답으로 만든다. 진짜 보기·`luck` 함정은 AI 가 쓰고 문구 검사를 통과해야 한다.
- **모범 답안 코드는 학생에게 가지 않는다.** 확정해서 저장할 때 `solution` 을 떼어낸다(Supabase `missions.data` 는 학생이 그대로 읽는다). 새 테이블은 만들지 않는다. **확정한 뒤에는 자료를 고쳐도 정답을 다시 계산하지 않는다** — 확정 후 자료를 바꾸려면 새로 만든다(4단계 화면에 그렇게 적는다). 자료별 정답 값(`expected`)은 저장해도 된다 — 지금도 파이프라인 미션의 정답은 학생 브라우저가 계산한다.
- **개념**: 미션에 `concept: '<개념 키>'` 를 저장한다(짝 문서가 쓴다).
- **예전 미션**(pipelineId 있는 것)과 기본 미션은 지금처럼 돈다. 지우지 않는다. 지금의 한 번에 만들기 경로도 "빠른 생성"으로 남긴다 — 지금 e2e(`e2e-flow.spec.js`)와 `test_missionguard` 14유형 검사가 그대로 지켜진다.
## 강사 화면

`teacher.html` 미션 탭의 "AI 미션 만들기" 자리가 네 단계가 된다. 한 화면 안에서 위에서 아래로 진행하고, 앞 단계로 돌아가 바꿀 수 있다.

- 1단계: 지금 입력칸(오늘 배운 것 / 핵심 / 난이도) + "개념 확인" → 개념 한 줄과 바꾸기(고정 목록에서 고르기). 이 동안 Pyodide 를 미리 불러 둔다.
- 2단계: 예시 카드 4~5장, 하나 고르기, "다른 예시 더 보기".
- 3단계: "이렇게 바꿔 줬으면" 자유 입력(선택, 200자) + "만들기". 이 자유 입력은 학생 화면에 가지 않는다. 진행 중 상태 문장(만드는 중 → 돌려 보는 중 → 다시 만드는 중)을 보인다.
- 4단계: 초안 확인. 제목·상황·요청·자료·카드·성공 보기 모두 고칠 수 있다(설문 검증 C8: 지금은 상황·성공 보기·카드를 못 고친다). 자료별 정답을 나란히 보이고, **자료를 고치면 그 자리에서 모범 답안을 다시 돌려 정답과 함정 보기를 다시 계산**하고 기계 검사를 다시 건다. 따로 풀기 결과가 오면 사실 한 줄로 붙는다. 확정하면 `solution` 을 떼고 교실에 저장.
- 반 레벨 분포는 지금처럼 2·3단계 AI 호출에 같이 넘긴다.
- 화면 배치(단계 표시 등)는 builder — 학생 화면의 `step-tabs` 꼴을 빌려도 된다.
## 서버

- 지금 `api/generate-mission.py` 옆에 새 함수 하나(예: `api/mission-steps.py`), `action` 으로 나눈다: `concept` · `examples` · `build` · `solve`. 같은 gateway(`https://llm.pcl.kr/v1/chat/completions`, `PICKLE_API_KEY`). action 하나 = LLM 호출 한두 번, 60초 안.
- `concept`: 먼저 이미 있는 `_generate.py` 의 낱말 규칙(`by_keyword` 류)으로 정하고, 못 정하면 AI(mini). 개념 키 고정 목록 8개: 문자열 나누기 · 리스트·인덱스 · if · for · while · 딕셔너리 · 집합 · 함수. (키 이름은 builder.)
- `examples`: 개념 + 난이도 + 반 분포 → 예시 4~5개. 서버가 길이를 검사한다(제목 + 상황 40자 안팎 + `→` 한 줄). 이미 보인 예시 제목을 받아 겹치지 않게.
- `build`: 개념 + 고른 예시 + 강사 입력 + (다시 만들기면) 걸린 이유 → 미션 초안 + 모범 답안. 서버는 실행하지 않는다. JSON 꼴·문구 규칙(`_schema.py`)은 서버가 먼저 건다.
- `solve`: 문제·자료만 → 풀이 코드(mini).
- **서버는 AI 가 쓴 코드를 실행하지 않는다.**
- **로그인한 강사만 (리뷰 M8)**: 새 함수는 Supabase 토큰을 받아 사용자·역할(teacher)을 확인한다 — `api/_accounts.py` 의 강사 확인 1·2단계를 공용 함수로 빼서 쓴다. 브라우저는 `js/data/supabase.js` 의 토큰 붙이는 방식을 data 층 함수로 재사용한다. 이건 비용 남용을 막는 장치지 보안 경계가 아니다(누구나 가입하면 강사) — 그래서 코드 실행을 서버에 두지 않았다.
- 지금 열려 있는 `/api/generate-mission`(빠른 생성)도 같은 확인을 건다. `/api/tutor` 는 학생도 쓰고 로컬 모드 영향이 있어 이번 범위에서 뺀다(보고서에 남은 일로 적는다).
## 목표 / 아닌 것

목표
- 강사가 개념과 소재를 고르고, 고른 그대로 문제가 나온다.
- while·if 숫자 비교·함수 수업도 그 개념이 꼭 필요한 문제가 나온다.
- 정답은 실행해서 얻는다.

아닌 것
- 블록 미션(`index.html` 계열)용 생성은 하지 않는다. 문장형(`sentence.html`)만.
- 강사 개인 소재 즐겨찾기·소재 라이브러리 저장은 하지 않는다(다음에).
- 학생별 다른 문제(개인화)는 하지 않는다.

하면 안 되는 것 (만들어도 실패)
- 예시가 길어서 강사가 안 읽는 목록.
- 고른 개념 없이도 풀리는 문제(지금의 실패 그대로).
- 학생 화면에 모범 답안·정답 값이 보이는 것, 정답 대조 채점. CLAUDE.md "만들면 안 되는 것" 표 전부 그대로.
- 브리프에 방법을 적는 것("for 문으로 더하세요"). 개념은 `→` 줄에서 **강사에게만** 보인다 — 학생 브리프에는 방법이 없다.

## 비용 (사람 요청: "비용 생각해서 진행해줘")

사람이 보여 준 gateway 사용량(2026-10-19 기준)으로 환산한 단가: `gpt-5.4-mini` ≈ $0.6/백만 토큰·1.7초, `gpt-5.4` ≈ $2.2/백만·3.4초, `claude-sonnet-5-5` ≈ $3.5/백만·4.7초, `gemini-2.5-flash` ≈ $0.6/백만·2.7초. 표에서 "금액 미기록" 줄은 모두 실패(시간 초과로 보임) — 긴 호출은 돈도 결과도 남기지 않는다.

- **단계마다 모델을 나눈다.** 개념 확인·예시 목록·따로 풀기 = `openai/gpt-5.4-mini`. 미션 만들기(모범 답안 포함) = `openai/gpt-5.4`. 모델 이름은 환경변수로 바꿀 수 있게(지금 `_generate.py` 의 MODEL 처럼).
- 개념 확인은 먼저 **글자 규칙**으로 해 본다("while", "반복", "딕셔너리" 같은 낱말 → 개념 키). 규칙으로 하나가 정해지면 AI 를 부르지 않는다.
- 다시 만들기는 최대 2번. 실행 검사에서 걸린 이유를 다음 요청에 붙여 한 번에 고치게 한다(지금 `_generate.py` 의 재요청 방식).
- 단위 시험은 전부 가짜 LLM(`test_generate.py` 방식). 실제 호출은 아래 완성 확인에서만.
- **완성 확인 예산: gateway 금액 $3 이내.** 넘을 것 같으면 멈추고 그때까지 결과를 적는다. 쓴 호출 수·토큰을 보고서에 적는다.

## 완성 확인 — 개념마다 2개씩 실제로 만들어 본다 (사람 요청)

사람의 말: "문제도 유형별로 2개씩만 생성해서 확인해봐봐. 내가 선택할만한 것 미리 나를 프로파일링해두고 그 기준으로 선택해도 돼."

- 개념 고정 목록의 **개념마다 2개**를 실제 LLM(운영과 같은 gateway·모델)으로 끝까지 만든다: 개념 확인 → 예시 목록 → 사람 대신 고르기 → (필요하면 "이렇게 바꿔 줬으면" 한 줄) → 만들기.
- **사람 대신 고르기 기준**(사람이 브레인스토밍에서 직접 말한 것):
  1. 짧다 — "설명이 너무 긴 것들은 나도 읽기 싫어서 별로"
  2. 현실적이고 왜 필요한지 보인다 — 매점 영수증 "현실적임", "가능한 시간대를 받아 언제 회의할 수 있는지"는 좋고 "간식 이름이 몇 번 나왔는지"는 싫다
  3. 쉽다 — 줄넘기 일주일 "예시 쉬움"
  4. 자료가 요일 이름만 바뀌는 반복은 싫다
- 결과를 `docs/eval-2026-10-20-stepwise-gen.md` 에 남긴다. 미션마다: 고른 예시와 고른 이유(위 기준 번호), 최종 미션 전문(상황·요청·자료·자료별 정답·카드·성공 보기), 기계 검사 결과, 따로 풀기 결과, 그리고 **사람 기준으로 본 솔직한 평** — 좋은 점 / 걸리는 점. 마지막에 개념별 한 줄 요약과 고칠 거리 목록.
- 걸리는 점이 구조적이면(예: while 개념이 계속 for 로 풀리는 문제가 나옴) 프롬프트·검사를 고치고 다시 2개를 만든다. 몇 번 돌렸는지도 적는다.
- 운영 사이트 배포 없이 로컬 서버(`vercel dev` 또는 함수 직접 호출)로 해도 된다. 교사 화면 4단계를 headless 로 한 번은 끝까지 눌러 본다(스크린샷 남김).

## builder 에게 남긴 것

- 새 미션 데이터의 정확한 필드 이름(위에서 정한 것: `kind`, `concept`, `inputs[].v` 리터럴 문자열, `cards`, `expected`, 저장 전 `solution` 떼기).
- 개념 키 이름, 개념 표의 노드 목록 세부.
- 4단계 화면 배치.
- 강사 화면에 Pyodide 실행기를 붙이는 방법(학생 화면 코드 재사용 정도).

## 사람에게 물을 것 (답이 오기 전에는 아래 기본값으로 진행)

1. 반례에 **경계값 축**(예: 키 정확히 140, 점수 정확히 60)을 더할까? — CLAUDE.md 규칙 변경이라 사람 결정. 기본값: 더하지 않고 개수 변화·빈 결과만.
2. 밤새 작업을 운영에 반영할까? — 기본값: 브랜치에서 만들고 시험까지만. merge·push·운영 DB 반영은 아침에 사람 확인 후.

## 순서 (리뷰 권고)

1. core: 자료 줄 함수 + 리터럴 자료, `cards.forMission` 의 `m.cards`, 개념 표 + 검사 함수(`solcheck`), 손으로 만든 새 꼴 고정 미션 하나로 학생 화면 끝까지(시험 포함)
2. 강사 화면 Pyodide 실행기
3. 새 API(`concept`/`examples`/`build`/`solve`) + 강사 인증(빠른 생성 포함), 가짜 LLM 시험
4. 강사 화면 4단계 + 저장 시 `solution` 떼기
5. 따로 풀기 비동기 연결
6. 완성 확인(개념마다 2개, 예산 $3)
7. 짝 문서(학생 코드 사실)
