# 온보딩 진단 · 튜터 완화 · 스토리형 문제 · 설계|코드 반반 화면

날짜 2026-10-17 · 기간 **3일** · 근거: 학생 설문(응답 2명), Supabase `student_events` 튜터 로그 25건

## 왜

설문과 실제 로그가 같은 이야기를 한다.

- **튜터가 막다른 길이다.** 질문 25건 중 19건(76%)이 거절됐고, 같은 거절 문장
  "코드는 직접 써 보는 거예요…" 가 14번 나왔다. 한 학생(메뉴 묶기, 34분)은
  "모르겟어요 → 코드 알려주세욤 → 우짜라는거야 → 제발" 로 감정이 올라갔고
  `print(data)` 한 줄로 끝났다. 설문에서도 둘 다 튜터가 "틀린 부분을 짚어줘요 / 힌트까지" 해주길 원했다.
- **튜터는 문제를 모른다.** LLM 은 `mission_title` 과 학생 코드만 받는다 (`api/_tutor.py:43`).
  문제 설명·자료·학생 설계·마지막 에러·직전 대화가 없다. 그래서 "그래서 뭐 우짜라는 거예요"
  같은 이어지는 질문이 매번 처음 듣는 질문이 된다.
- **막힌 곳은 문법이 아니라 조합이다.** 같은 학생이 split 과 딕셔너리 추가에 대한 답은 받았지만
  둘을 엮어 세는 데서 멈췄다. 그리고 "문자열이 뭐고" 를 물었다 (설문상 6개월 넘게 배움).
  → 반의 실제 수준을 모르고 문제를 만들고 있다.
- **하드코딩이 먼저 나온다.** 다른 학생의 첫 코드가 `print(2 + 3 + 5)` 였다 (결과를 보고 스스로 일반화함).
- **문제 설명이 어렵다 / 뒤로 가고 싶다.** 설문 응답("문제 설명, 순서 정하는 부분" / "뒤로가기버튼").
- 반대로 정규식 검사가 **방법을 흘린 답을 통과시켰다**: "쉼표로 나눈 뒤 묶는 단계가 필요해요".
  정규식은 너무 막으면서 정작 새는 건 못 막는다.

## 목표

1. 튜터가 **문제를 알고, 직전 대화를 기억하고**, "어떻게 써먹어요?" 에 답한다. 단 이 미션의 정답 코드·방법은 주지 않는다.
2. 출력 직전 **LLM 판정** 한 번이 정답·방법 유출을 막는다. 정규식 검사는 형식만 본다.
3. 학생이 반에 들어온 직후 **파이썬 진단 8문항**. 결과는 문제 생성의 난이도로만 쓴다.
4. 생성 문제의 `situation`·`brief` 가 **중학생 생활 장면 이야기**가 된다. 방법은 여전히 쓰지 않는다.
5. 04 코딩에서 **설계(왼쪽) | 파이썬 코드(오른쪽) 반반**, 문제 설명이 계속 보이고, 단계 탭으로 지난 단계에 돌아갈 수 있다.
6. 튜터 로그를 **수업 개선용 데이터**로: 이유까지 남기고, 교사가 CSV 로 내려받는다.

## 하지 않는 것

- 학생 화면에 진단 결과·레벨·점수 표시 (CLAUDE.md 금지 목록. `events.NEVER` 에 `level`·`score` 가 있다)
- 설계도 저장 복습, 자주 틀리는 부분 정리, 선생님 코멘트 확인 — 설문에서 둘 다 원했지만 다음 스프린트. 이벤트는 이미 쌓이고 있다.
- 가명화·보호자 동의 — 로그는 **수업 개선용으로만** 쓴다 (사람이 정함). 바깥에 낼 때 다시 연다.
- 레벨·뱃지 (설문 1명 X, 철학상 금지)

## 실패로 치는 것 (돌아가도)

- 튜터가 이 미션 자료로 동작하는 코드를 준다 → 학생은 다시 붙여넣기만 한다.
- 스토리 문장이 방법을 말한다. 사람이 든 예시 "딕셔너리에서 명성 키를 찾아 값을 추출해보자" 는
  **방법 공개라서 그대로 쓰지 않는다.** 이야기는 구체적으로, 끝은 목표만:
  "엄마가 명성이 번호를 물어봤어요. 내 연락처엔 있어요. 엄마한테 번호를 알려줘야 해요."
- 진단 결과가 학생에게 보이거나, 학생 간 비교가 생긴다.
- 서버가 없으면 진단·학습이 막힌다 (오프라인 우선 원칙).

## 1. 튜터 (1일차)

### 1-1. 튜터가 받는 맥락

`js/ui/sentence.js:38` 의 `context()` 와 `api/_tutor.py` 의 `ask()` 를 넓힌다. LLM user 메시지에:

| 칸 | 출처 |
|---|---|
| `situation`, `brief`, `itemName` | 미션 데이터 `M` |
| `inputs` (자료 예시) | `M.inputs` |
| `define` (학생이 고른 성공 조건) | 학생 상태 |
| `design` (학생 설계 카드 순서) | 학생 상태 |
| `student_code`, `last_output`, `last_error` | 에디터 · 마지막 `s-code` |
| `history` (같은 미션 직전 튜터 대화 **3턴**) | 튜터 모달 안 메모리 |

자료·설계는 **튜터가 이해하라고** 주는 것이지 답에 쓰라는 게 아니다 — 시스템 프롬프트에 그렇게 적는다.

### 1-2. 시스템 프롬프트 방향

- "문법만" → **"개념 설명, 학생 코드에서 틀린 위치 짚기, 일반적인 사용법 예시까지 된다."**
- "어떻게 써먹어요?" 는 받는다: 미션과 **다른 자료**로 쓰는 법 한 줄 (예: `"a,b,c".split(",")`).
- 막을 때 고정 문장을 반복하지 않는다. 대신 **학생이 다음에 확인할 것 한 가지를 묻는다**
  ("지금 data 를 print 하면 뭐가 나와요?"). 존댓말 유지 (반말은 `js/core/asks.js` 에만).
- 에러는 위치와 사실만: "6번째 줄에서 int 로 바꿀 수 없는 글자가 들어왔어요." 원인 결론은 학생 몫.
- 학생 설계와 코드가 다르게 가면 "설계 2번 카드랑 지금 코드가 같은 일을 하나요?" 처럼 되묻는다.
- 분류 `kind` 는 `answer` / `ask_back` / `off_topic` 으로 바꾼다. `solution_request` 도 거절 문장이 아니라 `ask_back` 으로 간다.
- 길이 200 → 300자.

### 1-3. 검사 두 겹

1. **정규식 (`api/_tutorguard.py`)** — 형식만: 길이, 백틱 예시 개수(≤2)·줄 수, 칭찬·'너'·반말, 한자/가나.
   지금 있는 "이 미션 / 정답 / 고치면 / 이렇게 하면" 단어 금지와 미션 항목 금지는 **뺀다** (판정이 맡는다).
2. **LLM 판정 (새 `api/_tutorjudge.py`)** — 답 하나와 미션·학생 코드를 보고 한 질문:
   **"이 답을 그대로 옮기면 이 미션이 풀리거나, 풀 방법(단계 순서)을 알려주는가?"** → `{leak: bool, why}`.
   패턴은 `api/_review.py` 를 따른다. `leak` 이면 이유를 붙여 1회 재요청, 또 걸리면 `ask_back` 고정 문장.
   판정 호출이 실패(타임아웃)하면 **답을 내보내지 않고** `ask_back` 으로 간다 (새는 쪽보다 막는 쪽이 안전).
   **시간 예산 (내가 정함):** `vercel.json` 의 `api/tutor.py` 한도는 30초. 답 생성 12초 + 판정 6초(작은 모델) = 1회전 18초.
   재요청은 남은 시간이 12초 이상일 때만 한 번. 그래서 LLM 호출은 많아야 3번(답·판정·재답)이고, 재답은 판정 없이 정규식만 거친 뒤
   판정이 처음 걸린 이유가 재답에 그대로 남아 있으면(같은 코드 줄 등) `ask_back`.

### 1-4. 로그 칸

`s-tutor` 이벤트에 `{ step, code, history_len, reasons, retried, judged }` 를 더한다 (서버 응답에 `reasons`·`retried` 추가).
판정이 막은 답, 판정 실패도 **모두 기록한다** (`kind: 'ask_back'`, `reasons` 에 `leak: …` 또는 `judge_timeout`). 막힌 원문 답은 남기지 않는다.
`kind` 값은 `syntax/solution_request/off_topic/guarded` → `answer/ask_back/off_topic` 으로 바뀌지만 겹치는 이름의 뜻은 같고
새 이름은 겹치지 않아 옛 기록과 섞여도 구분된다 → **스키마 버전은 그대로 (내가 정함).** `events.js` 주석에 두 세트를 다 적는다.
`NEVER` 에 걸리는 이름(`level` 등)을 쓰지 않는다.

## 3. 스토리형 문제 (2일차)

**AI 가 새로 만드는 미션에만 적용한다** (사람이 정함). `js/core/missions.js` 의 기본 미션 문장은 그대로 둔다.

- `api/_schema.py:247-253` 의 `situation`·`brief` 규칙, `api/_generate.py:33-46` 의 `SYSTEM` 을 바꾼다:
  `situation` = 중학생이 겪는 생활 장면 (가족·친구·학교·매점·단톡방), 인물 이름 하나 이상.
  `brief` = 그 장면에서 **무엇을 알아내야 하는지** 한 문장. 함수·자료구조·단계 이름 금지 (키·값·나누기·세기 등).
- 글자 수 `_LIMIT` (`_schema.py:173`): `situation` 30 → 90, `brief` 40 → 60. 화면이 늘어난 글을 받는지 확인.
- `api/_review.py` 판정 `noAnswer` 가 **이야기 속 방법 단어**를 잡게 기준 문장에 예시를 더한다.
- `test/test_missionguard.py` 에 스토리 예시 + "방법이 섞인 스토리는 걸린다" 케이스.

## 4. 온보딩 진단 (3일차)

### 흐름
가입 → 교실 코드로 들어감 → **진단 8문항 (교실마다 처음 한 번)** → 미션 목록.
검사는 `auth.html` 이 아니라 **`sentence.html` 에서 교실을 고르는 시점(`sentence.js:665` 부근)** 에 한다 —
로그인 분기(`auth.html:153-158`)는 이미 교실이 있는 학생을 바로 `sentence.html` 로 보내므로, 거기서만 막으면 기존 학생이 진단을 안 받는다.
그 교실에 내 `s-onboard` 이벤트가 없으면 진단 화면(새 `onboard.html?room=…`)으로. 교실이 여러 개면 교실마다 한 번 (교사가 자기 반 분포를 봐야 하므로, 내가 정함).
**서버가 없으면 진단을 건너뛴다** — 교실 자체가 Supabase 에만 있어서 로컬 모드에는 진단할 대상 반이 없다 (내가 정함).
교실에 들어간 뒤에 보므로 이벤트에 `classroom_id` 가 붙는다 → **DB 마이그레이션 없음.**
건너뛰기 가능 (막지 않는다). 건너뛰면 그 학생은 분포에서 빠진다.

### 문항 (모두 "코드 읽고 결과 고르기", 모든 문항에 **"모르겠어요"** 보기)

| # | 재는 것 | 형태 |
|---|---|---|
| 1 | 문자열 | `"3" + "4"` → 34 / 7 / 에러 |
| 2 | split | `"a,b,c".split(",")` 결과 |
| 3 | 인덱스 | `x = ["가","나","다"]; x[1]` |
| 4 | 반복 | for 가 몇 번 출력? |
| 5 | 조건 | if 분기 결과 |
| 6 | 딕셔너리 꺼내기 | `d = {"명성": "010-1234"}; d["명성"]` |
| 7 | 조합 | 딕셔너리로 개수 세는 5줄 코드의 출력 |
| 8 | 하드코딩 판단 | 코드 A `print(2+3+5)` · 코드 B `sum(...)`. data 가 `"1,1"` 로 바뀌면 각각 무엇이 나오나? |

화면에서 맞았는지 틀렸는지 알려주지 않는다. 다 고르면 "고마워요. 이제 미션을 볼 수 있어요." 하나.

### 저장과 해석
- 이벤트 `S_ONBOARD: 's-onboard'` `{ answers: [{q, pick}] }` — 고른 것만. 맞음·점수 칸 없음.
- 해석은 `js/core/onboard.js` 의 순수 함수 `stage(answers)` → `'base' | 'combine' | 'ready'`.
  1~3 중 '모르겠어요'·오답이 있으면 `base`, 7 에서 막히면 `combine`, 아니면 `ready`. 8번은 `hardcode: bool` 로 따로.
  정답표는 이 파일 안에만 둔다. 화면에 내보내지 않는다.
- `js/core/fold.js` 에 `case` 를 더해 학생 상태에 `onboard` 를 접는다 (교사 화면만 쓴다).

### 문제 생성에 연결
- `teacher.html` 은 이미 그 교실 이벤트를 읽는다. 생성 요청 때 학생들의 `stage` 분포
  `{base, combine, ready, hardcode}` 를 계산해 `difficulty` 와 함께 보낸다 (`teacher.html:477`).
- `api/generate-mission.py` 의 `do_POST`(`:35`) 는 지금 `difficulty` 를 아예 꺼내지 않는다. `difficulty`·`stages` 를 꺼내는 코드를 새로 쓰고 `_generate.generate()` 의 `ask` 에 넣는다 (지금은 버려짐).
  - `base` 가 많으면: 한 가지 개념만 쓰는 유형, 자료 3개 모두 짧게.
  - `combine` 이 많으면: 두 개념을 엮는 유형 (나누고 세기 등).
  - `hardcode` 가 많으면: 반례(`counter: true`)가 개수 변화 축을 쓰게.
- 교사 화면 생성 칸에 "이 반: 기초 n · 조합 전 n · 조합 가능 n" 한 줄. 학생 이름 순서나 개인 결과는 보이지 않는다.
  (교사 개인 학생 폴더에 진단 응답을 보이는 건 이번 범위 밖.)

## 내가 정한 것 (사람 확인 필요)

- 진단 결과는 학생에게 안 보이고 교사에게도 반 분포로만 보인다.
- 진단은 가입 직후가 아니라 **교실에 들어간 직후** (마이그레이션을 피하려고).
- 판정 실패 시 답을 막는 쪽으로. 튜터 1회 30초 예산과 LLM 최대 3번.
- 진단은 교실마다 한 번, 서버 없으면 건너뜀.
- 판정이 막은 답도 로그에 남김(원문 제외), 스키마 버전 유지.
- 튜터 대화 기억은 같은 미션 3턴, 새로고침하면 사라진다.
