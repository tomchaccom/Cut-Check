# /slide2 — 발표용 웹 슬라이드 설계

2026-10-21. 산학협력실무 발표. 교수님이 짚은 발표 포인트는 **퍼포먼스(시연)**.
기존 `/slides`(`slides.html`, 9월 진행 · 10월 계획)는 그대로 두고 새 주소 `/slide2` 를 만든다.

## 왜

말로 설명하는 발표가 아니라 **서비스를 실제로 쓰는 장면**으로 설득한다.
설문 결과 → 그래서 이렇게 설계했다 → 그 설계가 화면에서 이렇게 돈다, 를 한 흐름으로 잇는다.

## 순서 (사용자가 정함)

1. **표지**
2. **설문 → 설계 철학** — 설문 문항마다 그래프 + "이 결과 때문에 정한 것"(철학 한 줄 · 기능 이름)을 옆에 잇는다.
3. **AI 문제 생성 설계** — 단계별 흐름(수업 내용 → 개념 확인 → 이야기 고르기 → 문제 확인),
   파이프라인 도식(LLM 생성 → 검사(missionguard) → 강사 브라우저에서 모범 답안 실행 → 자료별 정답 → 강사 확정),
   단계마다 무엇이 걸러지는지, 마지막 자료는 늘 반례(다섯 축), 강사별 생성 한도.
4. **레벨 테스트 형식** — 하 · 중 · 상 문제지 예시 문항 몇 개(객관식 + 단답 한 낱말), 룰베이스 채점.
   학생 화면(맞음 · 점수 안 보임) 과 강사 화면(레벨 · 문항별 기록) 을 나란히.
5. **벡터 나침반 로직** — 방향별 예/아니오 3항목(코드 8 · AI 4) → 방향 점수 → x = 동 − 서, y = 북 − 남
   → 최근 5개 가중 평균 → 바늘. 단계별로 넘기며 바늘이 움직이는 애니메이션. 상쇄되면 강사가 고르는 장면으로 끝.
6. **핵심 플로우 시연** — 화면 반반: 왼쪽 강사, 오른쪽 학생 iframe(운영 사이트, 실제 로그인).
   미리 만든 미션으로 학생 01 → 05(튜터 질문 포함) → 강사 알림 → 학생 상세 나침반 → 한마디 → 학생 내 기록.
   단계마다 위에 자막 한 줄("지금 보는 것").
7. **마무리** — 만들지 않은 것(철학 표 요약) · 링크.

## 반드시 지킬 것

- **설문은 나중에 더하고 고칠 수 있어야 한다** (사용자 요구). 설문 데이터는 슬라이드 HTML 과 분리된
  데이터 파일 `slide2-data.js` 에 둔다 — `window.SLIDE2_SURVEY = [{ id, q, kind: 'choice'|'scale'|'quote', n, options: [{label, count}], quotes: [...], links: [{ philosophy, feature }] }]`.
  문항 하나를 배열에 더하면 슬라이드 한 장이 생긴다(2번 구간의 장 수는 데이터 길이로 정해진다). HTML 은 고치지 않는다.
  JSON 이 아니라 JS 인 이유: `file://` 에서 fetch 가 막힌다(저장소 규칙: ES 모듈 · 번들러 없음).
  데이터 파일 맨 위에 형식 설명 주석과 예시 한 문항을 둔다. 실제 결과가 아직 없으면 예시 문항에 "예시 데이터" 표시가 화면에 뜬다.
- **응답자는 응답자 A/B/C**, 학생은 학생 A/B/C. 실명 · 학교명 넣지 않는다.
- **그래프는 손으로 그린 SVG** — 라이브러리 없음(의존성을 늘리지 않는다). 막대 · 100% 누적 막대 · 인용 카드 세 가지면 충분.
- **나침반 · 생성 수치는 코드 값을 그대로** — `WEIGHTS = [1.0, 0.85, 0.7, 0.55, 0.4]`, `CANCEL = 0.5`, 바늘 길이 0.25–0.90(`api/_compass.py`),
  `TUTOR_MANY` · 반례 다섯 축 등. 슬라이드에 복사한 값이 코드와 갈라지면 테스트가 깨지게 한다(node 테스트 하나가 `_compass.py` 를 읽어 비교).
  나침반 그림은 화면과 같은 `js/core/compass.js` 의 `svg()` 를 불러 그린다 — 발표 그림과 실제 화면이 같은 코드.
- **두 iframe 은 서로 다른 로그인** — 같은 주소의 iframe 둘은 저장소를 같이 써서 학생으로 로그인하면 강사 칸도 바뀐다.
  (Vercel 의 다른 주소 별칭은 Vercel 로그인 보호가 걸려 iframe 으로 못 연다 — 2026-10-21 확인.)
  해결: iframe 에 `name="kompas-teacher"` / `name="kompas-student"` 를 주고, `js/data/supabase.js` 의 `createClient` 가
  `window.name` 이 `kompas-` 로 시작하면 `auth.storageKey` 를 그 이름으로 나눈다. `window.name` 은 그 iframe 안에서 페이지를 옮겨도 유지된다.
  일반 접속(이름 없음)은 지금과 같은 키 — 기존 로그인 그대로. 다른 localStorage 키(학생 발신함 · 강사 보기 편의)가 두 칸에서 부딪히는지 확인하고, 부딪히면 같은 방식으로 나눈다.
- **계정 비밀번호는 슬라이드에 넣지 않는다** — 시연 때 손으로 입력한다. 시연용 교실 · 학생 계정 · 미션은 발표 전에 강사가 만들어 둔다.
- **비상용** — 시연 단계마다 스크린샷(`docs/수업-흐름/` 의 그림 재사용, 부족하면 `test/shots.js` 로 찍기)을 두고,
  키 하나(`B`)로 iframe 대신 스크린샷을 보이게 한다. 와이파이가 끊겨도 발표가 멈추지 않는다.
- **조작** — ←/→ · 스페이스로 넘기기. iframe 에 초점이 있으면 키가 iframe 으로 가므로 화면 구석에 넘김 버튼을 항상 둔다.
  시연 장에서 iframe 을 크게(한 칸 전체) 보는 토글. 발표자 화면 · 노트는 만들지 않는다(YAGNI).
- **화면** — KOMPAS 색(노랑 · 흰 · 검정) · 새 아이콘. 16:9 프로젝터 기준(1920×1080, 1280×720)에서 읽히는 글자 크기.
  휴대폰 폭은 넘김만 되면 된다.
- **테스트** — `test/smoke.js` 의 화면 목록에 `slide2.html` 을 더한다. 금지 단어 검사는 슬라이드가 "점수 · 랭킹을 만들지 않는다"를
  설명해야 해서 `philosophy.html` 처럼 예외로 둔다. `node test/layer.test.js` 는 supabase.js 수정 뒤에도 통과(data 층은 `document` 를 모른다 — `window.name` 은 괜찮다).

## 설문 (원본: 강사용 "파이썬 수업에서 학생의 '의도' 확인하기", 2026-10-18~20, 강사 5명)

원본 xlsx 는 저장소에 넣지 않는다(이름이 들어 있다). `slide2-data.js` 에는 응답자 A–E 와 집계 · 인용만 옮긴다.
복수 선택 문항은 ", " 로 나눈 뒤 보기에 없는 글은 "기타" 로 센다. 2번 구간 슬라이드와 이어 붙일 설계:

## 만드는 사람에게 정해 둔 것 (설계자 판단 — 바꿔도 되지만 이유를 남긴다)

- `/slide2` 는 운영과 같은 출처(`cleanUrls` → `slide2.html`)에서 서빙하고 iframe 은 같은 출처의 `auth.html` 을 연다.
  운영 응답에 `X-Frame-Options` · `frame-ancestors` 없음(2026-10-21 curl 확인). 그래서 저장소가 겹치고, `window.name` 으로 나눈다.
- `createClient(url, key, name ? { auth: { storageKey: 'sb-' + name } } : undefined)` — 이름이 있을 때만 옵션을 넘긴다. 다른 auth 옵션은 건드리지 않는다.
- 검증 1순위: 학생 iframe 이 로그인 → `sentence.html` 로 옮긴 뒤에도 `window.name` 이 남고, 강사 iframe 은 강사 그대로인지 헤드리스로 확인(로컬 서버 + 가짜 Supabase 로 저장소 키가 갈리는지까지).
  `localStorage` 를 직접 쓰는 다른 키(`recap:` 캐시, 발신함, prefs)는 두 칸이 같은 키를 쓰면 실제로 섞이는 것만 나눈다 — 학생 발신함과 강사 prefs 는 역할이 달라 겹칠 일이 없으면 그대로 둔다.
- 설문 값은 위 표와 원본 집계로 처음부터 채운다(예시가 아니다). 1–5 척도 문항은 이름표를 받기 전까지 "1 ← → 5" 숫자 축으로 그린다.
- 비상용 스크린샷: `docs/수업-흐름/` 그림을 쓰고, 없는 장면(강사 알림이 뜬 순간 등)은 `test/shots.js` 로 찍는다 — 이번 범위.
- 레벨 테스트 구간은 `js/core/onboard.js` 를 불러 문항과 보기만 그린다. 정답 표시는 하지 않는다(`KEY` 는 밖으로 나가지 않는다). 문항은 파일에서 바로 읽으므로 따로 갈라짐 테스트는 두지 않는다.

## 하지 않는 것

- `/slides` 수정.
- 슬라이드에서 미션 생성 · 학생 계정 생성 같은 실제 효과 버튼을 자동으로 누르기.
- 차트 라이브러리, 발표자 노트 화면, 슬라이드 편집기.

## 정해지지 않은 것 (사용자에게서 받는다)

- 설문 결과 원본 — 받으면 `slide2-data.js` 에 옮긴다. 그 전까지는 예시 데이터로 만든다.
- 시연용 계정 · 교실 · 미션 — 발표 전 강사가 만든다.
