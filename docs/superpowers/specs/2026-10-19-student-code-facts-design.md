# 학생 코드 사실 — 강사에게만, 개념 사용 · 하드코딩

2026-10-19 · 사람과 브레인스토밍한 결과. 짝 문서: `2026-10-19-stepwise-generation-design.md`.

## 왜

사람의 말: "오늘 배운 개념이 적용되었는지. 그리고 하드코딩된 것은 아닌지. 설계도와 일치하는지 여부만 AI 가 먼저 판단해서 강사에게 보여주는 거지." 이어서 "설계도 일치 부분은 그러면 강사가 판단하는 부분으로 남겨두자."

설문 검증(`scratchpad/survey-check/report.md`)에서 드러난 틈과 겹친다:
- C4 — 학생이 자료 1만 돌리고 `print(3)` 을 "지켰다"로 끝낼 수 있고, 강사 화면에 반례를 안 돌렸다는 표시가 없다.
- C3/C6 — 설계와 코드를 맞대는 장치가 없다.

## 정한 것

| 항목 | 누가 판단 | 어떻게 |
|---|---|---|
| 오늘 개념을 썼는가 | **기계** (AI 아님) | 학생의 마지막 코드를 구조로 읽어(파이썬 `ast`) 미션의 개념에 해당하는 문법이 있는지 센다 |
| 하드코딩인가 | **기계** (AI 아님) | 학생 코드를 그 미션의 **모든 자료**로 돌려 본 결과로 판단 — 반례 자료의 결과가 자료 1 결과와 같은데 정답은 다르면 하드코딩으로 본다 |
| 설계도와 일치하는가 | **강사** | 강사 화면에 학생이 고른 설계 카드와 코드를 나란히 보여 줄 뿐, 시스템은 판단하지 않는다 |

AI 를 쓰지 않는 이유: 두 가지 모두 실행·구조로 **확실히** 알 수 있는 사실이다. 추측이 끼면 강사가 화면을 믿지 못한다. (브레인스토밍에서 이 제안에 사람이 "맞아"라고 했다.)

## 보이는 곳과 말투

- **강사 화면에만.** 학생 화면에는 아무것도 띄우지 않는다 — 결과가 보이는 순간 학생은 "맞히러" 간다(CLAUDE.md "정답 블록 순서와 대조하는 채점" 금지의 이유).
- **점수·통과/실패 배지가 아니라 사실 문장.** 강사가 말 걸 순간을 고르는 재료다. 예:
  - "오늘 개념 while 이 코드에 없어요"
  - "새로 온 자료(반례)에서도 자료 1과 같은 결과 3 이 나와요"
  - "새로 온 자료로는 실행하지 않았어요"
- 반 전체 정답률·순위·몇 명이 하드코딩했는지 같은 집계 숫자는 만들지 않는다(CLAUDE.md "교사 화면의 정답률·순위" 금지).
- 위치(builder 판단): 학생 서랍(`js/ui/teacher.js` 서랍의 "코드 실행" · "자료별 결과" 줄 근처)에 사실 줄로, 그리고 지금 있는 "말 걸기 좋은 순간"(`js/core/alerts.js`) 알림으로. 설계 일치는 서랍에서 **설계 카드 목록과 마지막 코드를 나란히**(지금은 위아래로 떨어져 있다).

## 데이터 흐름 (리뷰 M1–M4 반영, 내 판단)

**언제 돌리나 — 판정 저장 때 한 번 (M2).** 실행기는 worker 하나·대기 칸 하나이고, 무한 반복이면 5초 뒤 worker 를 죽이고 Pyodide 를 다시 불러온다(`sentence.js:327–389`). 실행마다 몰래 자료 수만큼 더 돌리면 학생 버튼이 몇 배 늦어진다. 그래서:
- 학생이 04 의 **판정을 저장(`s-code-judge`)할 때 한 번만**, 지금 코드로 미션의 모든 자료를 조용히 돌린다.
- 학생이 보이는 실행에서 에러·시간 초과였으면 건너뛴다(사실: "마지막 코드는 에러로 끝났어요" 는 이미 서랍에 있다).
- 두 번째 worker 는 만들지 않는다(학교 크롬북 메모리).
- 판정 저장 버튼은 이 실행을 기다리지 않는다 — 판정은 바로 저장, 조용한 실행은 뒤에서.

**어디에 남기나 — 새 이벤트 (M1).** 지금 `runWith` 는 실행마다 `s-code` 를 남기고, 그 기록이 학생 정리 화면 "실행 결과"와 강사 서랍 "자료별 결과"에 그대로 나온다. 조용한 실행이 거기 섞이면 학생 화면에 보인다. 그래서:
- 새 이벤트 `T.S_PROBE` = `{ code 의 짧은 지문(해시), outs: [{dataId, output, error}], uses: [노드 이름] | null }`. `runWith` 를 거치지 않는 별도 경로. `events.js` `T` + `fold.js` `case`, NEVER 필드(`correct`·`score` 등)에 걸리지 않게. 새 type 이라 스키마 버전은 그대로.
- `output` 은 200자에서 자른다. 학생 코드 출력은 학생 자유 입력과 같다 — `test/robust.js` 경로에 넣는다.
- `uses` 는 Pyodide 에서 `ast.parse` → `ast.walk` 로 뽑은 노드 이름 집합(+ `.split`·`dict(`·`set(` 같은 호출 이름). 구문 에러면 `null`(개념 줄을 띄우지 않는다).

**판단은 어디서 — `fold` 가 아니라 새 순수 모듈 (M3).** `fold` 는 미션을 모르고, 서버 board 도 같은 접기를 옮겨 심는다. 그래서 `fold` 는 마지막 probe 를 쌓기만 하고, 판단은 `js/core/facts.js`(학생 접힌 기록 + 미션 → 사실 문장 목록)에 둔다. 강사 서랍이 부른다.
- **하드코딩**: 마지막 probe 에서 반례 자료의 출력 == 자료 1 출력이면 "새로 온 자료(반례)에서도 자료 1과 같은 결과 X 가 나와요". **정답 값과 대조하지 않는다** — 새 미션은 만들 때 "반례 답 ≠ 자료 1 답"을 보장하므로 출력이 같다는 사실만으로 충분하다(채점 금지와 부딪치지 않는다). 예전 파이프라인 미션도 반례 규칙상 같은 보장이 있다. 어느 자료든 에러·시간 초과면 하드코딩 줄 대신 "자료 N 에서는 에러가 나요" 사실 한 줄.
- **반례를 안 돌림**: 학생이 보이는 실행으로 반례 자료를 한 번도 고르지 않았으면 "새로 온 자료로는 실행하지 않았어요"(이건 probe 와 상관없이 지금 `s-code` 기록으로 안다 — 설문 검증 C4).
- **개념**: 미션에 `concept` 가 있고 probe 의 `uses` 가 개념 표(짝 문서의 core 개념 표 — 같은 파일을 쓴다, 규칙은 한 곳)의 필요 노드를 하나도 갖지 않으면 "오늘 개념 while 이 코드에 없어요". 예전 미션은 `concept` 가 없으니 이 줄은 없다.
- 기준이 되는 "마지막 코드" = 마지막 probe.

**설계 일치 — 강사 판단, 나란히 보이기만.** 서랍에서 학생이 고른 설계 카드 목록과 마지막 코드를 좌우로 나란히(좁은 화면은 위아래). 시스템 판단 없음.

**알림**: `alerts.js` 머리말은 "판정 결과는 띄우지 않는다"다. 이번 범위에서 알림은 **넣지 않는다** — 서랍의 사실 줄만. (다음에 넣는다면 학생·미션마다 한 번, 사실 문장으로.)

## 목표 / 아닌 것

목표
- 강사가 서랍을 열면 "개념을 썼나 · 반례에서 깨지나"를 사실로 바로 안다.
- 강사가 설계 카드와 코드를 한눈에 맞대 볼 수 있다.

아닌 것
- AI 판정 없음. 설계 일치 자동 판정 없음(사람이 정함).
- 학생 화면 변화 없음.
- 반 전체 집계·순위 없음.

하면 안 되는 것
- 학생에게 "하드코딩이에요", "개념을 안 썼어요"가 보이는 것.
- 강사 화면에 맞음/틀림 배지나 점수.
