# 나침반 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 학생이 코드 결과를 처음 판정하면 서버가 루브릭으로 4방향 단계(0~3)와 벡터 바늘을 만들고, 선생님이 확인·한마디를 보내면 학생은 바늘 + 방위 이름 + 그 한마디만 본다.

**Architecture:** 판단 규칙(사실 계산 · 단계 상한 · 바늘 벡터)은 서버 `api/_compass.py` 한 곳에 있고, HTTP·권한은 `api/compass.py`, 저장은 새 테이블 `compass`(RLS 켜고 정책 없음, 학생은 RPC `compass_mine` 으로 열 제한 읽기). 선생님 화면은 알림·조용한 따라잡기·카드, 학생 화면은 카드 하나.

**Tech Stack:** 정적 JS(번들러·ES 모듈 없음), Vercel Python 함수, Supabase(Postgres RPC), 기존 `_steps.mini_llm`, Playwright e2e.

**Spec:** `docs/superpowers/specs/2026-10-20-compass-design.md`

## Global Constraints

- 단계 값은 방향마다 정수 0~3. 0~100 점수 없음.
- 4방위만: `N` 북쪽 · 이해 / `E` 동쪽 · 설계 / `S` 남쪽 · 구현 / `W` 서쪽 · 검증. 사이 방위 이름 없음.
- 바늘: `x = E − W`, `y = N − S`, `needle_deg = atan2(x, y)` 를 도(°)로, 북 0° 시계 방향, [0, 360). 길이 `hypot(x, y) < 1` 이면 `needle_deg = null`, `strongest = null`.
- 방위 이름 = 바늘이 속한 부채꼴: N [315,45) · E [45,135) · S [135,225) · W [225,315). 경계 값은 왼쪽 닫힘 그대로(45 → E). (스펙의 "경계면 북→동→남→서 먼저"는 반열린 구간으로 대신한다 — Ruling 은 아래.)
- 선생님이 방위를 고르면: 바늘이 그 부채꼴 안이면 그대로, 밖이거나 null 이면 정중앙(N 0 · E 90 · S 180 · W 270).
- 학생에게는 `needle_deg`, `teacher_dir`, `teacher_note`, `sent_at` 만. `levels` · `evidence` · `ai_note` 는 절대 안 간다.
- 레벨(0~3) 이벤트 금지: 이벤트(`student_events`)에 단계를 넣지 않는다.
- 강사 화면에서 단계로 정렬·평균·순위를 만들지 않는다. "한마디 기다림" 표시에 개수·순서 없음.
- 학생 문구: 존댓말, 카드 제목 `내 나침반`, 선생님 문장은 그대로(거르지 않음, textContent).
- 로컬 모드(서버 없음): 나침반 UI 없음, 알림 문구 `코드 결과를 판정했어요.` 그대로.
- AI 호출은 학생·미션당 한 번. `force` 는 선생님 "다시 읽기"만. 생성 한도 차감 없음.
- 서비스 키·PICKLE_API_KEY 를 응답·로그에 넣지 않는다. 응답 에러는 한국어 짧은 문장.
- CLAUDE.md 의 테스트 전부 통과해야 커밋. `git add` 는 경로 지정만.

사실(`kind`)과 방향, 상한 규칙 — 이 표가 루브릭이다:

| dir | kind | 언제 | 상한 효과 |
|---|---|---|---|
| N | `define` | `s-define` 있음 | 없으면 N≤0 |
| N | `trap-avoided` / `trap-fixed` | 마지막 성공 조건이 미션 `trap` 보기가 아님 / 처음엔 trap 이었다가 `s-redefine` 로 바꿈 | 둘 다 없으면 N≤1 |
| N | `reason` | define/redefine 의 reason 이 비지 않음 | 없고 튜터 질문도 없으면 N≤2 |
| E | `design` | `s-design` 또는 `s-method` | 없으면 E≤0 |
| E | `remethod` | `s-remethod` | 없으면 E≤1 |
| E | `remethod-reason` | remethod reason 이 비지 않음 | 없으면 E≤2 |
| S | `run` | `s-code` | 없으면 S≤0 |
| S | `fixed-error` | error 있는 `s-code` 뒤에 다른 code 로 다시 `s-code` | 없으면 S≤1 |
| S | `counter-clean` | 반례 자료로 에러 없이 실행했고 `facts.js` 의 hardcode/error 사실이 없음 | 없으면 S≤2 |
| W | `judge` | `s-code-judge` | 없으면 W≤0 |
| W | `basis` | 마지막 judge basis 가 비지 않음 | 없으면 W≤1 |
| W | `counter-fix` / `predict` | 반례 실행 뒤 code 나 성공 조건을 바꿈 / `s-predict` 있음 | 둘 다 없으면 W≤2 |

`text` 는 강사가 읽을 사실 문장(존댓말 아닌 평서 사실, 예: `반례 자료로 에러 없이 실행했다`). hardcode 판정은 `facts.js` 규칙을 그대로 옮겨 심는다(`sig` 대조 포함).

Rulings:
- 경계 각도 처리 — 스펙 "북→동→남→서 먼저" 대신 반열린 부채꼴 [315,45)… 로 정한다. 정수 단계에서 경계(45°·135°…)는 `|x|==|y|` 일 때뿐이고, 그때 어느 쪽을 붙여도 사실과 어긋나지 않는다. 틀리면 `needle()` 한 줄을 바꾸면 된다.
- 학생이 다시 판정해도 다시 분석하지 않는다는 스펙에 맞춰, 분석 입력은 analyze 시점의 전체 이벤트다(첫 판정 시점으로 자르지 않는다). 따라잡기 분석이 늦게 돌면 그 사이 기록도 들어간다 — 더 많은 사실이라 손해가 없다.
