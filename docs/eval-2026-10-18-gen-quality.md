# 미션 생성 품질 전후 비교 — "요일만 바뀐 간식 세기" 고친 뒤 (2026-10-18)

실제 `make_mission()`(유형 고르기 → 초안 → 검사·재요청 → 폴백 → LLM 검수)을 진짜 LLM 으로 돌렸다.
전: `.superpowers/sdd/tutor-fix/gen-eval-report.md` 의 기준 실행(코드 수정 전). 후: 이 브랜치의 코드, `openai/gpt-5.4`.
수업 셋 — 집합 = `파이썬 집합의 활용법 / 함수를 이용해서 값을 추가하고 수정하는 법`, 딕셔너리 = `딕셔너리 / 개수 세기`, split = `문자열 split / 쉼표로 나누기`. 후는 수업마다 2회.

"전" 은 검수 항목이 넷뿐이라 1회차 통과가 쉬웠다 — 그때 통과한 미션에 "몇 가지 ↔ 모두 몇 개", "겹쳐도 한 번만 세어" 가 있었다.

시간: 검수가 새 항목(sameAsk)으로 한 번 떨어뜨리면 재생성 한 바퀴(약 9초)가 붙어 18초, 재요청 + 상황 92자 초과까지 겹친 1회가 32초였다. 모두 `DEADLINE` 55초 안이다.
호출당 최대 13초 기준 계산은 `api/_generate.py` 의 `DEADLINE` 주석에 있다(재요청 2회 + 검수 = 46초, 그 뒤 재생성은 남은 시간 25초 조건에서 멈춤).

중간 시도(같은 코드, 검수에 자료를 `이름: 값` 한 줄로 넘기던 판, 6회)는 cleanData 가 자료 이름을 항목으로 잘못 읽어 3회 연속 떨어뜨렸고 평균 19.8초·최대 36.5초였다. 자료를 `{이름, 항목}` 으로 나눠 넘긴 뒤 위 6회에서 cleanData 오탈락은 0이다.

## 남은 걱정

- **목적 문장이 한 틀로 모인다.** 6/6 이 "…알아내서 …정해 주세요". 모델은 SYSTEM 의 예 모양을 그대로 따른다. 목적이 억지인 것도 있다 — split-count 의 "준비물이 모두 몇 개인지 알아내서 모둠 준비물을 정해 주세요" 는 개수로 무엇을 정하는지가 약하다(유형 자체가 단순 개수라서).
- **집합 수업은 아직 '두 사람 모두' 로 오지 않는다.** 2/2 가 `split-filter-unique-count`. 고정 목록은 자료에 없는 항목이 섞여 정답 누출 검사를 통과했지만, 요청 "세 사람 목록에서 같은 간식 이름만 골라 몇 가지인지" 는 "같은 것만 골라" 로 방법 쪽에 가깝고 셋째 사람(반례)은 01 화면에 아직 안 보인다.
- **sameAsk 는 아직 흔들린다.** 묶어 세기(“몇 번씩”)를 "몇 가지 살지" 와 비교해 떨어뜨린 1회가 있었다. 재생성으로 통과했지만 시간이 붙는다.
- 상황 90자 한도에 두 문장 목적을 담다 92·94자로 넘어 재요청이 2회 났다. 요청 60자는 넘은 적이 없어 그대로 뒀다.
