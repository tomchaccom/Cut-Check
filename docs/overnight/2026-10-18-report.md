- "그 문법을 사용하는 방법" → `지금 문자열에서 각 메뉴를 따로 보려면 글자를 어떤 기준으로 나눠야 하나요?`

- "그러면 딕셔너리를 이용해서 … 예시를 보여줘" → `입력을 쉼표로 나눈 뒤, 없는 메뉴면 1로 넣고 있는 메뉴면 1을 더하는 방식으로 직접 바꿔 볼 수 있나요?`
판정을 통과한 answer 중 풀이 순서가 보이는 것 (4회차):
- "ㅇㄴ 답이 아니라 ㅠ저 코드를 쓰는 문법과 방법을 알려주세욤" → `딕셔너리는 `이름[키] = 값`으로 넣고, 같은 키가 이미 있으면 값을 바꾸는 식이에요. 예를 들어 `count['김밥'] = 1`처럼요. 메뉴를 세려면 먼저 메뉴를 하나씩 꺼내서, 있으면 `+1`, 없으면 1로 넣는지 확인해야 해요. `dict.get(키, 기본값)`도 자주 써요. 한 줄 예시: `count['김밥'] = count.get('김밥', 0) + 1``

### 이어서: 답 생성 프롬프트
`_tutor.py` SYSTEM 에 두 줄: 예시 값은 미션 자료·학생 변수에 없는 것("a,b,c", 다른 이름), 학생의 data 같은 변수에 쓰는 코드는 쓰지 않는다. 풀이 순서(~한 뒤 ~) 금지, 풀이를 물으면 확인할 것 하나를 되묻는다. 정규식은 그대로.
- 리플레이 1회: 거절 17/25(직전) → 19/25, judge_failed 1, 504 2건. 표는 이 실행.
- 개념 질문 6건: answer 3/6 → 2/5(1건 504), 고정 문장 3(형식 1·판정 2).
- 미션 자료를 그대로 쓴 예시: 직전 실행·탐침 3건 → 1건. 탐침 "split은 뭐예요?" 예시가 `"a,b,c"` 로 바뀜. "떡볶이,우동 개수 세는 코드 알려줘" → 되묻기 `자료 1은 글자 하나짜리 항목이 아니라 쉼표로 나뉜 목록으로 나눴나요?`
- 풀이 순서·방법이 판정을 통과한 것은 줄지 않았다 (원문):
  - "ㅇㄴ 그게 아니라ㅠ…" → `메뉴를 한 개씩 보면서 세면 돼요. 딕셔너리에서 `메뉴이름`이 이미 있으면 값에 1을 더하고, 없으면 1로 넣어요. … 문법은 이렇게 써요: `counts[menu] = counts.get(menu, 0) + 1` … 반복문으로 메뉴를 하나씩 꺼내서 이 한 줄을 실행하면 돼요.`
  - "그러면 딕셔너리를 이용해서 … 예시를 보여줘" → `메뉴를 하나씩 보면서, 이미 있으면 1 더하고 없으면 1로 넣는 방식이 맞나요?`
  - "코드는 직접 써보는거예요…" → ``data = "떡볶이,우동,김밥,우동"`에서 문자열을 변수에 넣었어요. 지금 `print(data)`는 그대로 출력만 하니, 먼저 메뉴를 나눠서 묶을 준비를 해야 해요. 예: `name = "a,b,c"``
  - "코드를 직접 못쓰겟어요" (재답) → `딕셔너리에 메뉴 이름을 키로 넣고, 값은 몇 번 나왔는지 저장할 건가요?`
- 판단: 예시 값 문제는 생성 쪽에서 줄었다. 딕셔너리 세기 방법(있으면 +1, 없으면 1)은 판정이 "개념 설명"으로 보고 통과시킨다 — 학생이 딕셔너리 문법을 물은 흐름이라 경계가 실제로 모호하다. 사람이 정할 것: 이 미션의 핵심 관용구(`get(x, 0) + 1`)를 개념으로 볼지 풀이로 볼지.
