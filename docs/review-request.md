# 리뷰 요청 메시지 초안

도호님·소윤님께 보낼 메시지. 그대로 복사해서 쓰면 된다.
아래 질문 다섯 개를 먼저 박아두는 게 핵심이다 — 좋은 말만 들으면 시간 낭비라서,
**어디가 틀렸는지를 물어보는 형태**로 던진다.

---

```markdown
@도호 @소윤 Cut & Check 프로토타입 리뷰 한 번 부탁드립니다!

중학교 1학년 대상 컴퓨팅 사고력 학습 도구인데, 지금 미션 5개랑 선생님 화면까지 붙어 있습니다.
로컬 서버로 열어주셔야 학생 화면이랑 선생님 화면이 연결됩니다.

    git clone https://github.com/tomchaccom/Cut-Check.git
    cd Cut-Check
    python3 -m http.server 8000

`localhost:8000` 으로 들어가시고, 우측 상단 **설계 의도 보기**를 켜고 보시면
각 UI가 어떤 원칙 때문에 그렇게 돼 있는지 주석이 붙습니다. 이 상태로 보시는 걸 추천드립니다!

### 먼저 읽으실 것

- `docs/philosophy.md` — 설계 철학 전문입니다. 길면 `philosophy.html` 을 브라우저로 여셔도 됩니다
- `CLAUDE.md` — 만들면 안 되는 것 목록입니다. 왜 안 만들었는지 이유를 다 붙여놨습니다

한 줄로 요약하면 **시작은 대신해주고, 판단은 하나도 대신하지 않는다** 입니다.
기존 코딩 교육이 이 둘을 반대로 한다고 보고 있어서, 그걸 뒤집은 게 이 제품입니다.

### 특히 봐주셨으면 하는 것

좋은 점보다 **틀린 데**를 봐주시면 좋겠습니다. 다섯 개만 부탁드립니다!

1. 1단계(성공 조건 고르기) 잠금이 **생각을 강제하는 것**인지 **막막함을 만드는 것**인지요.
   중1 기준으로 보시면 좋겠습니다. 여기가 이 제품에서 제일 논쟁적인 부분이라고 생각합니다
2. 3장 검증에서 세 번째 주문서가 깨졌을 때, 학생이 **포기**할 거 같으신지 **고칠** 거 같으신지요
3. 선생님 화면(`teacher.html`)에서 **한 번도 안 보실 것 같은 칸**이 있는지요.
   있으면 그건 제가 틀린 거라 지울 생각입니다
4. 미션 05 동료 검토에서 코멘트를 질문형으로만 쓰게 막아뒀는데, 이게 실제로 지켜질 거 같은지요.
   "그냥 알려주면 되는데" 하고 말로 알려주면 이 장치는 무력화됩니다
5. 미션 03(실험 계획서)이 **억지로 갖다 붙인 것**처럼 보이는지요.
   전이를 제품 구조로 증명하려고 넣은 건데, 억지로 보이면 근거가 안 됩니다

### 제가 아직 모르는 것

- 45분 안에 어디까지 갈 수 있을지 감이 안 옵니다. `docs/lesson.md` 에 시간 배분을 짜뒀는데
  현장 기준으로 말이 되는지 봐주시면 좋겠습니다
- 전이(다른 과목으로 넘어가는 것)는 자기보고 말고는 잴 방법을 못 찾았습니다.
  혹시 아이디어 있으시면 알려주세요!

편하실 때 보시고 코멘트 남겨주시면 감사하겠습니다. 고생하셨습니다~
```

## 보내기 전에 확인할 것

- 저장소가 비공개면 두 분을 **collaborator 로 먼저 추가**해야 `git clone` 이 된다
- GitHub Pages 를 켜두면 클론 없이 볼 수 있지만, **학생→선생님 실시간 연결은 Pages 에서도 된다**
  (`file://` 로 직접 열 때만 막힌다). Pages 로 보실 거면 URL 만 주면 된다
- 질문 3번(안 볼 것 같은 칸)의 답은 받아 적기만 하고 그 자리에서 변호하지 않는다.
  변호하면 다음부터 솔직한 답이 안 온다
