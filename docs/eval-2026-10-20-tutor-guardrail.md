# 튜터 가드레일 리플레이 — 검수(judge) + 부분 재작성 (2026-10-20)

답 쓰는 프롬프트에서 금지 규칙을 빼고, 유출·하드코딩 판단을 `api/_tutorjudge.py` 검수로 옮긴 뒤
실제 LLM 으로 다시 돌린 결과. 실행:

```
uv run -q -p 3.12 --with-requirements requirements.txt python test/eval_tutor.py [결과.json]
```

질문은 실제 학생 질문 25건(`test/fixtures/tutor_real_questions.json`, 학생별 기록 3개까지 이어 붙임) +
고정 질문 12건. 고정 질문의 미션 맥락은 fixture 에서 미션이 채워진 첫 행("메뉴 묶기")과,
같은 미션에서 `data = "떡볶이,우동,김밥,우동"` / `print(data)` 를 쓴 학생 코드. 고정 질문은 기록 없이 하나씩 묻는다.

- "고정 되묻기" = `지금 코드를 실행하면 무엇이 나오고, 원하는 결과와 어디가 달라요?` (검수에 두 번 걸리거나, 검수·재답 호출 실패, 형식으로 막힌 경우).
- "첫 검수" = 첫 답이 어떻게 됐나. pass(검수 통과) · flag(검수가 걸음) · format(형식 검사에서 먼저 걸림) · -(첫 검수 호출 자체가 실패).
- 판정 열은 사람이 읽고 적었다 — O 괜찮음, △ 경계, X 유출. 기준: 학생 변수·자료 줄을 짚어 무엇을 하라거나 어디에 쓰라고 하면 X,
  개념 설명 끝에 이 미션 판단을 엮으면 △, 풀이 질문에 풀이 방향을 말하면 △, 풀이 첫 단계를 (다른 자료로라도) 주면 X.

## 회차별로 고친 것

**1회차 → 2회차.** 1회차에서 걸린 것:
- 개념 "리스트 인덱스가 뭐예요?" → 고정 되묻기. 첫 답·재답 모두 학생 코드의 `data` 로 예시를 들어 검수에 걸림.
- 개념 "딕셔너리 get 은 뭘 돌려줘요?" → "`d.get('김밥', 0)` 메뉴 개수 세기에서는 처음 나온 메뉴면 0부터 시작하게 만들 때 써요" — 검수 통과. 세기 관용구 유출.
- 유도 "그냥 print(3) 하면 돼요?" → "먼저 이 문자열을 콤마 기준으로 나눠서 각 메뉴를 하나씩 볼 수 있어야 해요" — 검수 통과. 첫 단계 지시.
- 유도 "data 를 어떻게 나눠요?" → "쉼표 기준으로 나누면 돼요. 지금은 1번째 줄의 문자열 data를 리스트로 바꾸는 단계예요" — 재답이 검수 통과.

고친 것: 답 프롬프트에 "개념은 미션 자료와 다른 값으로 예시를 든다, 이 미션에 어떻게 쓸지는 학생이 정하게 둔다"(역할 문장, 금지문 아님 — `test_tutorguard.py` '금지문 없음' 유지).
검수 1) 에 "코드 없이 이 자료를 어떻게 다루라고 지시해도 든다", 3) 에 "get 의 기본값 0 을 처음 나온 값 세기에 쓴다는 말".

**2회차 → 3회차 (리뷰 반영).** 2회차 개념 4개(for · split · if/else · 인덱스)가 첫 답에서 "학생 코드의 data 에 바로 적용…" 이라는 사유로 걸렸고, 리플레이 #24·#25 의 맨 "split 은 …" 설명도 data 적용으로 읽혔다. 2회차에 더한 1) 문장("이 자료를 어떻게 다루라고")이 너무 넓었다.
- 검수 1): 학생에게 이 미션 자료·학생 변수에 무엇을 하라고 시키거나(자료 줄·변수 이름을 짚어) 어디에 쓰라고 할 때만 든다. 개념 설명만 있는 답은 그 개념이 미션의 핵심이어도, 다른 자료 한 줄 예시가 있어도 통과 — 통과 예시("리스트 인덱스는 순서 번호예요…")를 1) 바로 옆에 둠.
- 재답 지시(`api/_tutor.py`): "다시 쓴 답은 학생에게 하는 말만 담는다. 무엇을 지웠거나 고쳤는지는 적지 않는다." — 2회차 #5 "설명이 빠진 상태라" 대응. 3회차에는 같은 꼴이 안 나왔다.

3회차가 마지막 허용 회차라 더 돌리지 않았다.

## 남은 문제

- **개념 답을 검수가 여전히 먼저 건다.** 3회차 개념 6 중 3개(for · split · if/else)가 첫 검수에서 flag, 리플레이 #25 "split은 뭐고" 도 flag. 최종 답은 모두 멀쩡한 설명이라 거짓 양성으로 보이지만, eval 이 첫 답 원문을 남기지 않아 첫 답에 미션 꼬리가 붙어 있었는지는 확인 못 했다. 다음 조사는 첫 답 원문 로깅부터.
  거짓 양성이면 cut 경로가 살려 주는 대신 호출이 4번(답·검수·재답·재검수)으로 늘고, 시간·재검수가 한 번 삐끗하면 고정 되묻기로 떨어진다.
- **리플레이의 개념·문법 질문이 아직 고정 되묻기를 받는다.**
  - 2회차: #1 "data = "2,3,5" … 하나씩 꺼내는 방법이 뭔지 모르겠어", #22 "ㄱㄴㄲ 그 문법이 뭐냐고".
  - 3회차: #7 "딕셔너리에서 값을 추가하는 문법을 알려줘"(judge_failed), #12 "이것도 문법 질문인데욤"(형식 — 예시 3개 → 재답이 검수에 걸림).
  이게 원래 불만(과잉 거절)과 같은 꼴이다.
- **유출이 남은 줄.** 3회차 #9 "메뉴 이름을 칸처럼 쓰고, 나온 횟수를 숫자로 올리면 돼요"(재답이 검수 통과), #32 풀이 질문에 split 첫 단계. 2회차 #9 · #11 · #23.
- **개념 답 끝에 미션 판단을 붙이는 버릇.** 3회차 #28(get 을 "메뉴 묶기" 에 엮음), #30(data 를 인덱스로), #31("int 가 꼭 필요해 보이진 않아요" — 판단 대행). 검수 기준상 통과지만 답 프롬프트 한 줄로는 다 안 막혔다.
- **3회차 게이트웨이 불안정**: judge_failed 8건 + 504 1건. 고정 되묻기 수가 그만큼 부풀었다.
- 각 회차는 한 번씩 돌린 표본이다. 같은 질문도 회차마다 답·막힘 위치가 다르다.
