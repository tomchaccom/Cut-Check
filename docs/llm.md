# LLM을 붙일 때의 계약

지금 AI 되묻기는 사전(`js/asks.js`)이다. 나중에 LLM이 그 자리를 채운다.
**이 문서는 그때 철학이 무너지지 않게 하는 계약이다.**

문서에만 적어두면 반드시 무너진다. 프롬프트를 아무리 잘 써도 모델은 가끔 친절해지고,
친절해지는 순간 우리가 만든 나머지 장치가 전부 무의미해진다.
그래서 규칙을 **실행 가능한 코드**(`js/llmguard.js`)로 박아두고, 위반하면 폐기한다.

---

## 1. 허용되는 출력은 두 가지뿐

| 모드 | 무엇 | 형식 |
|---|---|---|
| `ask` | 학생에게 되묻는 질문 | 반드시 물음표로 끝난다 |
| `fact` | 어디서 멈췄는지 알리는 사실 | 질문이 아니고, 무엇에 대한 사실인지 명시한다 |

그 외는 전부 거부한다. 요약도, 격려도, 요령도 없다.

---

## 2. 거부 규칙

`js/llmguard.js` 에 정규식으로 박혀 있다. 규칙마다 **왜 막는지**가 붙어 있다.

| 규칙 | 예시 | 왜 막는가 |
|---|---|---|
| 칭찬 | "잘했어요!", "훌륭해" | 인정은 사람의 일이다. 기계가 대신하면 그 자산을 태운다 |
| 해법 지시 | "자르기 블록을 넣으세요" | 답을 받은 학생은 고치기만 하고 왜 그런지 모른 채 넘어간다 |
| **위장된 해법** | "자르기를 **넣고** 다시 돌려보면 어때?" | 질문으로 끝나지만 답이다. 실무에서 제일 흔한 누수 |
| 원인 진단 | "자르기 블록이 **없어서** 안 나뉜 거야" | 학생이 스스로 찾아야 할 결론이다 |
| 코드 조각 | `items = text.split(",")` | 베껴 쓸 정답 공개 |
| 80자 초과 | — | 중1은 안 읽는다. 안 읽으면 없는 것과 같다 |

### 위반하면 어떻게 하나

**절대 "그냥 내보내기"를 하지 않는다.** 한 번 새면 신뢰가 무너진다.
폴백 문장으로 갈아 끼운다.

```js
guard(llmOutput, 'ask')
// → { ok: false, text: '지금 네가 만든 순서를 처음부터 한 번 읽어볼래?', reasons: [...] }
```

`reasons` 는 로그에 남긴다. 어떤 규칙이 얼마나 자주 걸리는지가 프롬프트 개선의 유일한 근거다.

---

## 3. 우리 문장부터 검사한다

`test/llmguard.test.js` 는 **우리가 실제로 쓰는 문장 전부**를 같은 규칙으로 검사한다.
사전에 있는 되묻기 4개, 엔진이 뱉는 에러 메시지 7개가 대상이다.

> 우리 손으로 쓴 문장이 규칙을 못 지키면, 모델에게 지키라고 할 자격이 없다.

실제로 이 검사가 우리 문장 하나를 잡아냈다.

```
FAIL fact: 데이터를 받는 블록이 없어서 아무것도 흐르지 않았어요.
     → 원인 진단 — 학생이 스스로 찾아야 할 결론이다
```

"블록이 **없어서**"가 원인을 대신 짚어주고 있었다.
`아직 어떤 블록에도 값이 흐르지 않았어요.` 로 고쳤다 — 상태만 말하고 원인은 말하지 않는다.

---

## 4. 시스템 프롬프트 초안

```
너는 중학교 1학년 학생의 논리 학습을 돕는다.
너의 유일한 일은 학생이 다음 생각을 스스로 하게 만드는 것이다.

절대 하지 않는 것
- 답, 정답, 고칠 방법, 넣어야 할 블록을 말하지 않는다
- 왜 안 되는지 원인을 대신 짚어주지 않는다
- 코드를 쓰지 않는다
- 칭찬하지 않는다. 칭찬은 선생님이 한다

하는 것
- 학생이 방금 쓴 문장이나 고른 선택을 되비춘다
- 한 번에 질문 하나만 한다
- 40자 안팎으로 쓴다. 절대 80자를 넘기지 않는다
- 반말로 쓴다. 학생과 같은 편에 서 있다는 신호다

받는 것 (컨텍스트)
- 학생이 1단계에서 고른 성공 조건
- 학생이 2단계에서 고른 자를 기준과 이유
- 현재 블록 순서
- 3장 실행 결과
- 학생이 쓴 증상 진술 (기대값 / 실제값 / 의심 블록)

출력은 질문 한 문장. 물음표로 끝낸다.
```

**컨텍스트에 정답 블록 순서를 넣지 않는다.** 넣으면 모델이 그걸 흘린다.
모델도 정답을 모르는 상태에서 되묻게 하는 게 가장 확실한 방어다.

---

## 5. LLM이 필요 없는 자리

전부 LLM으로 바꾸려는 충동을 경계한다. 아래는 사전이 더 낫다.

- **에러 메시지** — 엔진이 위치를 정확히 안다. 모델이 끼면 틀릴 여지만 생긴다.
- **증상 진술 보기** — 선택지가 고정이어야 교사 화면에서 집계된다. 자유 생성하면 집계가 깨진다.
- **동료 검토 코멘트 템플릿** — 문장 수가 적고 바뀔 일이 없다.

LLM이 실제로 필요한 자리는 하나다 — **학생이 직접 쓴 문장**(직접 쓴 성공 조건, 자유 서술 이유,
직접 쓴 증상)에 반응할 때. 그것 말고는 사전으로 충분하다.

---

## 6. 교사에게 보내는 출력은 규칙이 다르다

학생에게는 답을 주지 않지만, **교사에게는 사실을 명확히 준다.**

- 학생: "아까 성공이 뭐라고 정했었지?" (질문)
- 교사: "지우가 1단계에서 하드코딩 보기를 골랐습니다." (사실)

단 한 가지는 교사에게도 안 한다 — **칭찬 문구를 대신 써주지 않는다.**
타이밍만 알려주고 말은 교사가 한다. 격려의 효과는 그게 사람에게서 왔다는 데서 나오기 때문이다.

---

## 7. 검증

```bash
node test/llmguard.test.js
```

통과해야 하는 문장보다 **거부해야 하는 문장을 더 많이** 넣어둔다.
이 검사기의 일은 통과시키는 게 아니라 막는 것이다.
