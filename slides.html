프로젝트 개요

Cut & Check가 뭔가요?

중학생이 문제를 정의하고, 방법을 정하고, 실행하고, 스스로 판정하는 수업 도구입니다.
파이썬 문법이 아니라, 문법이 바뀌어도 남는 사고 방식을 가르칩니다.

핵심 원칙

시작은 대신해주고, 판단은 하나도 대신하지 않는다.

핵심 기능

학생 화면

문장 입력형 미션

코드 대신 빈칸 선택. 성공 조건 → 방법 3문장 → 자료별 실행·판정 → 마무리

학생이 직접 판정

시스템이 채점하지 않음. "내 성공 조건을 지켰나요?" 학생이 지켰다/못했다/어렵다 선택

마무리 돌아보기

자료별 판정 카드를 다시 보면서, 가장 기억에 남는 걸 자기 언어로 정리

내 기록

문제 원문 + 내가 한 판단 + 원본 데이터 + 판정·근거. 이벤트 로그 아닌 사람 언어

핵심 기능

강사 화면

교실 관리

교실 생성 → 참여 코드 → 학생 목록. 한 강사가 여러 교실 운영

AI 미션 생성

수업 내용 + 핵심 입력 → LLM이 맞춤 미션 생성. 수정/삭제 가능

개입 순서 대시보드

정답률 대신: 조용히 막힌 학생, 도움 요청, 칭찬 타이밍, 위험군

학생 활동 실시간

Supabase를 통해 학생 이벤트 수집 → fold → 대시보드 반영

10/1~10/3 검증 + 수정

3개 검증 에이전트를 병렬 실행해 데이터 흐름·AI 품질·대시보드를 검증하고, 발견된 문제 9건을 수정.

데이터 흐름 검증

학생 이벤트 → Supabase → fold → 강사 대시보드 전체 경로 추적.
발견: RLS 정책 2건(enrollments/profiles), currentMissionDbId undefined, quiet() 오탐.
수정: RLS 정책 추가, null 명시, 문장형 활동 체크.

AI 미션 품질 검증

5회 호출 테스트. 중복 검증 5/5 통과.
발견: 주제 4/5가 "도서관", 조사 오류 "같은 도서은".
수정: 프롬프트 다양성 강제, hasJongseong() 받침 판별.

강사 대시보드 검증

문장형 학생이 대시보드 5개 패널에 안 보이는 구조적 갭 발견.
발견: tiles/risk/funnel 중복, praise() 필터 누락, quiet() 오탐.
수정: innerHTML 초기화, praise에 문장형 조건 추가.

데이터 검증 대시보드

debug.html 신규 — 연결 상태 5개, 학생 활동 테이블, 미션 테이블, AI 테스트를 한 페이지에서 확인.
